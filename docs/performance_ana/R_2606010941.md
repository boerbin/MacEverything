## 10. P0 优化建议（7 条 + 资源平衡说明）

1. **阀门下调 0.25 → 8–10%**（`IndexPersistence.cpp:159`）：墓碑八连涨破 22.09%、reclaim 恒为 0，阀门是墓碑只增不减的直接闸门。
2. **无锁快照刷新 / 读写解耦（TOP）**：本轮 `MacEverything` 单次冷页错失（phase2 仅 1.61ms 却 lockHeld 209ms，§5）再次显示——任何读路径慢操作都在持锁窗口内放大。让查询读不可变快照、flush 经指针交换发布，可同时切断争用与持锁放大。
3. **按簇密度的风暴护栏**（滚动窗口背靠背计数）：08:36–38 密集簇是损伤源头；护栏基于"窗口内重写次数"。
4. **全扫尾部护栏（string 线性层）**：path 再探尾部仍冲 558ms（§3）。为 linear-gcd 路径设预算 / 分段让出，封顶并发抖动。
5. **dm 列驻留 / page-state**：dm 干净 42ms，floor 探测中偶冲 112ms（并发抖动）。固定列页驻留。
6. **string 读路径页驻留 / 重写后预热（持续 TOP）**：平台"易累积、难清空"的不对称（§6）强烈支持"大重写驱逐 mmap 索引页、查询负载下逐页 re-fault 缓慢回暖"。应在大重写后主动预热 string 槽页或 `madvise(WILLNEED)` 锁定读路径热页，把"多小时缓降"压缩到秒级。
7. **刷新门控压力治理（本轮升格）**：SKIPFLUSH 连续两轮加速（+5 → +10）。应排查 `IndexPersistence` 刷新门控为何跳过激增（pending 阈值 vs 实际写入速率失配），避免刷新债务无限累积放大后续重写时长。

**资源平衡说明**：7 条全部是 **I/O 调度 / 并发控制 / 页驻留 / 门控参数**类改动，**无一以内存换计算或以计算换内存**。#2 无锁快照在 flush 期间额外占用"一个索引指针版本"的有界瞬时内存（交换后即释放）；#6 页驻留用 `madvise` 提示，不复制数据、不新增常驻大表；#7 为门控阈值调参，零额外内存/计算。**未引入大内存表，未新增重计算**——内存与计算成本平衡。
