### `size:>100m` 异常分析

- queryTimeMs=2,731,551ms（~45 分钟），但 phase2Ms=2,751ms（2.8 秒）。
- **时间差异**：2,731,551 - 2,751 = **2,728,800ms（~45 分钟）花在非 phase2 阶段**。
- **根因**：pure-filter-soa-gcd 路径在 phase2 前需获取锁并遍历全量记录做过滤。在极端 I/O 压力下，内存页面频繁换入换出，遍历 600 万条记录的元数据需要大量随机磁盘 I/O。
- lockWaitMs=0 表示锁获取本身不是瓶颈——**瓶颈是锁持有期间的页面换入**。
- **这是 tombstone 膨胀的极端后果**：122MB tombstone + 正常索引内存 → 系统内存压力 → 大量页面被换出 → 全表扫描触发海量页面换入 → 45 分钟。
