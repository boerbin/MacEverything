## 6. 问题清单

### P0：flush 完整重写仍有分钟级灾难长尾

- 证据：rewrite 最大 895,940ms，total 最大 896,053ms。
- 最新 flush 虽从 4016ms 回落到 2304ms，但仍是秒级完整重写。
- 根因：完整索引重写在 APFS COW、系统 I/O 压力、睡眠/唤醒或后台任务竞争下被放大。

### P0：flush 频率继续上升且没有退避

- 证据：最新 session `FLUSH=310`，较上一轮 +12；`SKIPFLUSH=0`。
- 影响：高频完整重写持续污染 page cache，导致 11:48 到 12:18 这种前台性能大幅波动反复出现。

### P0：tombstone 继续上升并逼近 9%

- 证据：tombstone=505,069（8.74%），较上一轮增加 14,209。
- 影响：索引体积、flush rewrite 成本和扫描成本继续扩大。

### P1：full-scan 性能恢复但稳定性不足

- 证据：full-scan 总和 978.3ms → 586.0ms，但同一最新 session 内仍有历史 `中文测试` 555/716ms 与 `path:/Users` 525ms。
- 影响：当前可接受，但 page cache/SoA 热区仍可能在后台 I/O 后再次降温。

### P1：dm filter 仍偏高

- 证据：`dm:today`=65.7ms，高于 <50ms 健康线，但较上一轮 145.4ms 明显恢复。
- 判断：pure-filter SoA 路径仍受缓存热度影响。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 8.7%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对搜索热区使用 `madvise` 预热/保持。
