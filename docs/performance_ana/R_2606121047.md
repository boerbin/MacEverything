## 6. 问题清单

### P0：flush 完整重写仍有分钟级灾难长尾

- 证据：rewrite 最大 895,940ms，total 最大 896,053ms。
- 最新 flush 为 2737ms，仍是秒级完整重写。
- 根因：完整索引重写在 APFS COW、系统 I/O 压力、睡眠/唤醒或后台任务竞争下被放大。

### P0：flush 频率继续上升且没有退避

- 证据：最新 session `FLUSH=274`，较上一轮 +12；`SKIPFLUSH=0`。
- 影响：高频完整重写持续污染 page cache，增加 full-scan 慢查询反复出现的概率。

### P0：tombstone 已突破 8%

- 证据：tombstone=465,679（8.12%），较上一轮增加 8,250。
- 影响：索引体积、flush rewrite 成本和扫描成本继续扩大；如果继续按当前速率增长，后台持久化压力会继续升高。

### P1：full-scan 虽回暖但仍受 page cache 波动影响

- 证据：full-scan 总和从 820.2ms 降到 579.3ms，但历史同 session 内仍有 `中文测试` 555/716ms 与 `path:/Users` 525ms 慢查询。
- 影响：当前用户态可接受，但稳定性不够，下一轮仍可能反弹。

### P2：`content:import` 出现小幅 lock wait

- 证据：`content:import` lockWait=2.5ms。
- 判断：当前很小，不构成瓶颈；但可作为前台查询与后台持久化/索引更新竞争的早期信号继续观察。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 8%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对搜索热区使用 `madvise` 预热/保持。
