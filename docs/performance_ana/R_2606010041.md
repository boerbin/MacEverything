## 10. P0 优化建议

1. **比率阀 reclaim 立即下调 0.25→8–10%（最高优先）**：523 秒 rewrite 已用数据证明墓碑债务到期的代价 —— 墓碑 20.46%、连续 31 轮运行期 compaction=0，全量 rewrite 扫描 6.86M 记录。25% 阀门已被彻底证伪，必须立即让运行期 reclaim 可达。
2. **storm guard 必须按 rolling flush 簇 + 单次时长双触发**：本轮单次 523s + 余震簇 32s/14s/17s 是最强风暴信号；guard 不应只看查询是否跨 500ms，应在单次 rewrite 超阈（如 >30s）或簇内累计超阈时主动降频、分片或延后后续 flush。
3. **rewrite 必须分片/增量化（针对 523s 根因）**：单次全量重写 6.86M 记录是 523s 的直接原因；需要把 flat index rewrite 改为增量/分段，避免单次 flush 锁定或占满 I/O 长达数分钟。
4. **读写解耦 / lock-free snapshot flush**：本轮探测全部落在风暴内，W2 size 首探被推到 431ms、trigram 冷首探到 319ms，证明 rewrite 页态会污染读路径；查询应读取稳定快照而非被 rewrite 页态拖拽。
5. **full-scan tail guard**：中文电池 360ms、path 264ms、content 250ms，`advanced-linear-gcd` 与 pure-filter 字符串路径需要批处理让步、时间片上限或可中断扫描。
6. **查询超时/熔断**：本轮查询侥幸未跨 500ms，但 523s rewrite 同窗内 size 已达 431ms；应保留上层超时与降级，避免下一次灾难簇直接把用户查询推过秒级。
