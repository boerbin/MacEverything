### 锁竞争根因分析

**最可能原因：flush timer 触发了索引写入，持有写锁 ~500-600ms。**

- `content:import` 是 battery 第 13 个查询——执行到此时，可能恰好遇到 flush timer 的写锁窗口。
- FLUSH 仍为 1（未新增 flush），但 SKIPFLUSH +21（间隔短于正常 +60）——说明在 battery 期间 flush timer 被频繁检查。
- phase2=1105ms 本身也很高——说明 SoA 数据区域的 page cache 也被严重淘汰。
- **lockWait=567ms 是独立于 page cache 的问题——纯锁竞争。**

### 这是 P1 COW flush 的最强证据

- **lockWait=567ms 意味着用户查询被阻塞 >0.5 秒等待锁释放。**
- **用户体感：输入查询后 0.5 秒无响应——不可接受。**
- **COW flush 可以将 lockWait 降至 ~0ms——flush 操作不需要持有写锁。**
- **建议将 P1 升级为 P0.5——仅次于 compaction 修复。**
