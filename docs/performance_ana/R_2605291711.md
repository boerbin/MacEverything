## 3. 两种退化模式模型（R61 补全）

跨 R56→R61 的数据揭示文件系统活动爆发可触发**两种独立的退化模式**：

```
文件系统活动爆发（外部，不可控）
   │
   ├─模式 A：I/O 缓存驱逐 ──→ 数据页/trigram 桶页被逐出缓存
   │   （R56, R61）            ├─ phase2/trigram 膨胀
   │                          ├─ lock=0
   │                          └─ flush 节奏正常
   │
   └─模式 B：压缩/WAL 锁竞争 ──→ 持久化操作持排他锁
       （R58）                 ├─ lockMs 巨大 / 查询超时
                              ├─ 持久化线程静默间隙
                              └─ 候选后段查询锁释放后恢复
```

- **R57 是过渡态**：I/O 爆发峰值 + 首次 lock=799（两模式叠加）。
- **R61 是最纯净的模式 A 样本**：完全无锁，纯数据页冷缓存。
- 两模式同源（文件系统爆发），但机制与表征不同，需**分别施治**：模式 A 靠缓存预热/常驻（mlock 关键页 / 预读），模式 B 靠无锁化 + 持锁限流。

### 为何 R60（33K/h）快、R61（35.7K/h）慢？

二者 tombstone 增速接近、均零锁，但 R60 全程快、R61 全程慢。差异在**查询时刻的缓存温度**：

- R60：爆发均匀分摊，查询窗口缓存仍热；
- R61：30 分钟空闲间隔 + 本区间文件系统活动（tombstone +17,860）的内存churn，在 17:11 查询前驱逐了工作集页面 → 查询撞上冷缓存。

这印证 R60 的核心论断——**退化由查询时刻的瞬时状态（缓存温度 / 锁占用）决定，而非平均 tombstone 增速**。35.7K/h 本身不致命，致命的是它恰好在查询前驱逐了缓存。

> 诚实声明：冷缓存的诱因有两种可能——① MacEverything 自身文件系统爆发驱动的索引/WAL 内存churn 挤占读缓存；② 30 分钟空闲期间外部进程内存压力回收了读缓存页。本区间 tombstone +17,860 证明确有文件系统活动（支持①），但无逐进程内存日志，无法完全排除②。两者都指向同一工程结论：**关键数据页需缓存常驻保护**。

### R61 新增论证：关键数据页缓存常驻（P0）

R61 证明仅靠"无锁化"不足以根治——即使零锁（模式 A），冷缓存仍致 14x 退化。phase2 候选过滤需读取大量分散的记录数据页，对文件系统缓存极度敏感。建议：
1. **关键索引结构 mlock 常驻**（trigram 桶、SoA 记录列），防止 OS 在空闲期回收；
2. **phase2 候选页预读**（madvise WILLNEED），降低冷启动磁盘延迟；
3. 评估**SoA 列式存储的页局部性**——当前 phase2 扫描候选记录时若跨页跳跃严重，冷缓存代价被放大。
