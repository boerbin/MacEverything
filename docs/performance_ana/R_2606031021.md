## 6. 问题清单

### Critical：服务停机约 40+ 小时无自动恢复

- 证据：2026-06-01 16:57 compaction done 之后进程退出，直到 2026-06-03 09:17 手动重启。
- 日志仍未解释进程退出原因。

### High：FSEvents replay 失败导致全盘重扫

- 证据：`FSEvents replay failed — background full scan`，rescan 耗时 181.7 秒。
- 影响：每次重启都需要近 3 分钟才能完成初始化。

### High：`.pdf` 查询 9221ms — trigram 候选爆炸

- 证据：candidates=9881，phase2=8250ms。`.pdf` 仅产生极少 trigram（`.pd` `pdf`），posting list 交集仍然过大。
- 对比：精确查询如 `MacEverything` 仅 27ms。

### Medium：DIAG-TRIGRAM SKIP 大量出现

- 证据：53 次 SKIP，`useTrigram=false, allFound=0, rawCands=0`。
- 影响：常见词搜索（config, application, readme, node_modules）退化为线性扫描。

### Medium：`x` 短查询缓存路径仍需 1923ms

- 证据：走 short-query-cache 路径但 queryTimeMs=1923.6。
- 可能原因：缓存未命中或缓存重建中。

### Low：tombstone 率 25%（加载时）

- 证据：7,329,551 loaded vs 5,497,246 live。
- compaction 后已恢复至接近无 tombstone（5,718,601 live）。

## 7. 优化建议

### P0：补齐进程生命周期可观测性

- 添加 signal handler 记录进程退出原因（SIGTERM/SIGKILL/crash）。
- 注册 launchd 或其他 watchdog 实现自动重启。

### P0：修复 FSEvents replay 可靠性

- FSEvents replay 失败导致每次重启都全盘重扫（181.7s）。应调查 replay 失败原因并增加重试机制。

### P1：优化 `.pdf` 类短 trigram 查询

- `.pdf` 仅有 2-3 个 trigram，交集候选过多。可引入扩展名索引快捷路径：检测到 `.xxx` 模式时直接走 ext-index 而非 trigram 索引。

### P1：降低 sqcache 重建开销

- sqcache 重建 11733ms 占 Phase 2 总耗时 44%。考虑增量更新而非全量重建。

### P1：调查 DIAG-TRIGRAM SKIP 根因

- `allFound=0, rawCands=0` 说明 trigram 索引未找到任何候选。可能是 trigram 索引为空或查询词的 trigram 在索引中不存在。需确认 Phase 2 完成后是否正确使用了 trigram 索引。

### P2：优化 `x` 短查询缓存性能

- 短查询缓存路径接近 2 秒不合理。检查缓存是否已预热。

## 8. 下一轮重点

1. 确认 FSEvents replay 失败的根因。
2. 监控服务稳定性——确保不再出现无预警停机。
3. 追踪 DIAG-TRIGRAM SKIP 在后续查询中是否持续出现。
4. 比较本轮与历史活跃轮次的 query 性能基线。

MacEverything 服务在经历约 40+ 小时停机后已于 2026-06-03 09:17 恢复。Query battery 16 个查询全部完成，大多数查询性能正常（P50 ≈ 189ms），但 `.pdf` 查询仍是最大 outlier（9221ms），`x` 短查询也偏慢（1923ms）。新问题包括 FSEvents replay 失败（导致 181.7s 全盘重扫）和 53 次 DIAG-TRIGRAM SKIP。最高优先级是补齐进程生命周期监控以防止再次无预警长时间停机，以及修复 FSEvents replay 可靠性。
