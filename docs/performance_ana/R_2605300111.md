## 3. 🔑 R75 核心发现：线性路径运行间方差——数值地板稳、字符串覆盖层抖

R74 报告称「线性/纯过滤路径跨冷暖稳定（1.3–2×），与 trigram 700× 波动相反」。本轮用**同一暖轮、相隔 3 分钟**的两次探测（01:11 探针 vs 01:14 电池）做了一次更严格的复现检验，结论需要拆细——不是「整体稳定」，而是「**地板稳、覆盖层抖**」。

### 3.1 两次读数对照（同一暖轮，相隔 ~3 分钟）

| 查询 | 路径类型 | 01:11 ms | 01:14 ms | 比值 | 01:11 ns/槽 | 01:14 ns/槽 |
|------|---------|----------|----------|------|------------|------------|
| `size:>100m` | 纯数值 SIMD（无字符串） | 45.35 | 46.67 | **1.03×** | 7.95 | 8.18 |
| `dm:today` | 纯数值 SIMD | 73.08 | 114.22 | 1.56× | 12.82 | 20.03 |
| `content:import` | 纯过滤（标志位） | 160.49 | 204.79 | 1.28× | 28.15 | 35.91 |
| `path:/Users` | linear full-eval（取路径串） | 206.69 | 256.58 | 1.24× | 36.25 | 44.99 |
| `中文测试` | linear full-eval（取名字串、0 命中全比对） | **308.51** | **177.72** | **0.58×** | 54.11 | 31.16 |

> ns/槽 = totalMs × 1e6 / 总记录数（R75 ~5.70M）。

### 3.2 解读：方差来源是字符串池页温度，不是 type 列扫描

- **唯一真正稳定的是 `size:>100m`：8.0↔8.2 ns/槽（Δ 2.9%）。** 它扫 `types_`/数值列、做纯数值比较，零字符串解引用——这验证了 R74「O(N) 地板稳定」的**那一半**：type 列/数值列每次扫描都被触达、始终驻留，扫描本身确实恒定。
- **`中文/path/content` 是 full-eval，对每条 live 记录加载并比较名字/路径字符串**，命中字符串池（5.38M live 记录的串数据，远大于 type 列）。串池页在查询间会部分变冷/变热，故这些路径 1.2–1.7× 抖动。`中文测试` 最极端（CJK 无 trigram → 0 命中 → 必须全比对每条名字、无早退），是字符串池页温度的**最大暴露面**，故方差最大（54→31 ns/槽）。
- **R74 单次读数报「ns/槽 恒定」（`中文` 39.9）是欠采样**：本轮 `中文` 在 31–54 ns/槽间，叠加 R73 的 43.5——真实区间是 ~31–54，并非常数。

### 3.3 修正后的结论（取代 R74 的「整体稳定」）

线性/纯过滤路径 = **稳定的 O(N) 数值地板（`size` 8 ns/槽恒定）** + **页温度敏感的字符串比较覆盖层（`中文` 31–54 ns/槽抖动）**。两层的优化策略不同：
- 数值地板：靠 §4 的 tombstone 回收缩小 N（线性收益、可预测）；
- 字符串覆盖层：与 trigram 同源——需 mlock 串池热页 / 按访问局部性重排，才能压住方差。

这说明 trigram 与「线性 full-eval」其实**共享同一个冷缓存根因（字符串/SoA 页驻留）**，只是 trigram 暴露面（散落候选行）波动更猛（700×），full-eval 暴露面（顺序串池）波动较缓（1.2–1.7×）但绝对值更高。**mlock/madvise P0 同时治理这两者**，杠杆比 R74 设想的更高。
