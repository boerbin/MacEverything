## 9. 可能问题定位

### P0-1：Rewrite 后 page-cache 扰动导致 full-scan 冷态慢查询

证据：

- 13:07 与 13:09 出现 `11,723ms`、`8,793ms` rewrite。
- 13:12 `content:import` 记录 `537ms` 慢查询。
- 同一 query 在 W2/reprobe 后 floor 降至 `50.30ms`。

根因判断：content pure-filter 的慢查询更像 page residency 问题，而不是算法每次都需要 500ms。rewrite 可能驱逐或扰动 content/string 相关页，导致后续第一次扫描在锁内承担大量 page fault。

### P0-2：Full-scan/page-access 成本仍发生在锁持有区间

证据：

- `content:import total=235.61ms / phase2=224.45ms / lockHeld=224.45ms`。
- `path:/Users total=335.67ms / phase2=330.64ms / lockHeld=330.64ms`。
- `中文测试 total=373.85ms / phase2=340.47ms / lockHeld=356.50ms`。

根因判断：即使热化后 floor 下降，冷态扫描仍会把 page fault 成本转化为锁持有时间。这是并发和尾延迟的根因风险。

### P0-3：Runtime reclaim 阀门仍过高，23.34% tombstone debt 无法触发回收

证据：

- 本轮最终 `tombstoneRatio=23.34%`。
- 日志段 `COMPACTION=2 / RECLAIM=0`。
- 相比上一轮，tombstones 增加 `18,402`，live records 只增加 `2,478`。

根因判断：系统持续在 23% tombstone ratio 附近运行，扫描面和 rewrite 压力持续抬升，但 25% runtime reclaim valve 仍未触发。

### P1：热状态下列访问差异缩小，但 content/path/中文仍明显高于 size/dm

证据：

- `size=0.51ns/slot`，`dm=1.76ns/slot`。
- `content=7.03ns/slot`，`path=6.30ns/slot`，`中文=6.08ns/slot`。

根因判断：热化可以消除大部分冷页成本，但字符串/路径/内容列本身仍比数值/日期列慢 3–14 倍，需要继续优化列布局和字符串访问路径。

## 10. 优化建议

### P0：rewrite 后对 content/path/string 页做 targeted prewarm

- 在 rewrite 完成后，对 content/path/trigram 字符串页执行轻量预热，或使用 `madvise(WILLNEED)` 提示关键 mmap 区域。
- 目标不是把所有数据常驻内存，而是降低 rewrite 后第一批 query 的冷页尖峰。
- 验收标准：`content:import` W1 不再出现 500ms+，W1/W2 差距显著缩小。

### P0：降低 runtime reclaim threshold，或改为 debt-based 复合触发

- 当前 `tombstoneRatio=23.34%` 已足够造成扫描面和 rewrite 压力，但仍 `RECLAIM=0`。
- 建议把单一 25% 阀值降到 8–10%，或使用 `tombstone ratio + tombstone absolute count + recent rewrite density` 的复合触发。
- 验收标准：`RECLAIM>0`，tombstone ratio 回落到 10% 以下，full-scan cold floor 不再随 tombstones 上升。

### P0：读写解耦，避免锁内承担 full-scan/page fault

- 查询获取不可变 snapshot 后释放全局锁，flush/rewrite 通过 pointer swap 发布新结构。
- 优先处理 `advanced-pure-filter-soa-gcd` 与 `advanced-linear-gcd`，因为它们的慢查询表现为 `lockHeld≈phase2≈total`。
- 验收标准：冷态慢查询的 `lockHeldMs / totalMs` 明显下降；即使 content/path 冷页慢，也不阻塞全局读写。

### P1：rewrite density guard

- 当短窗口内出现多个 ≥5s rewrite，尤其是连续 ≥10s rewrite 时，合并、推迟或降频后续 rewrite。
- 本轮 13:07 与 13:09 的连续长 rewrite 后 13:12 出现 content 慢查询，说明密度护栏有直接价值。
- 验收标准：`FLUSH_GE5` 和 `FLUSH_GE10` 增速下降，慢查询事件不再紧跟 rewrite cluster 出现。

### P1：列级 page-touch 观测

- 为 full-scan 路径增加列级指标：访问槽数、字符串 dereference 数、慢页估计、跳过数、编码匹配耗时。
- 用 `size` 和 `dm` 作为数值/日期列基线，对比 `content/path/中文` 的额外成本。
- 验收标准：能解释 `size=0.51ns/slot` 与 `content/path/中文=6–7ns/slot` 的热态差距，以及 W1 冷态 537ms 的来源。

## 11. 结论

本轮出现一个新的 ≥500ms 慢查询：`content:import=537ms`。但重复探测显示它不是稳定计算平台退化，而是 rewrite/page-cache 扰动后的冷态 full-scan 慢查询；热化后 content/path/中文 floor 可降到 `43–50ms`。真正的风险仍在根因层：`tombstoneRatio=23.34%`、`RECLAIM=0`、`FLUSH_GE5=140`、`FLUSH_GE10=23`，加上 full-scan 成本仍在锁内执行。优先级应放在 rewrite 后 targeted prewarm、降低 reclaim 阀值、读写解耦和 rewrite density guard 上。
