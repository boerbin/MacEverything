## 6. 问题清单

### P0：tombstone 在 13% 以上继续快速上行

- 证据：tombstone=809,585（13.26%），较上一轮增加 11,962。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：这已经不是临界状态，而是持续越线；compaction/清理策略明显滞后。

### P0：pure-filter 路径成为本轮尾部主因

- 证据：`content:import`=293.8ms，phase2=283.9ms，searchPath=`advanced-pure-filter-soa-gcd`。
- 影响：虽然未超过 500ms，但已经接近 300ms，且与 tombstone、page-cache 状态相关时可能继续上行。
- 判断：主要耗时在 phase2 过滤/扫描阶段，不是 lockWait。

### P0：flush 高频且没有退避

- 证据：`FLUSH=706`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=2780ms。
- 影响：完整重写仍维持秒级并持续污染 page cache，可能导致扫描查询在不同轮次间大幅波动。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径缺少切分、退避和前台保护，是当前最主要的系统性风险。

### P1：扫描尾部在不同路径间转移

- 证据：上一轮最高为 `中文测试`=345.7ms，本轮最高变为 `content:import`=293.8ms；`path:/Users` 仍有 209.4ms。
- 影响：单项回落不能代表根因改善，scan/filter 系列路径整体仍是用户可感知尾延迟来源。

## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 scan/filter 路径继续扫描大量无效记录。
- 验收：tombstone 率从 13%+ 回落，`content:import`、`path:/Users`、`中文测试` 稳定 <200-300ms，扫描/过滤总和持续下降。

### P0：为 advanced-pure-filter-soa-gcd 增加剪枝与观测

- 对 `content:import`、`dm:today`、`size:>100m` 记录扫描记录数、tombstone 跳过数、过滤命中/丢弃原因和排序耗时。
- 评估 segment-level skip list、预过滤位图或按字段维护轻量统计，减少低选择性过滤的全量扫描。
- 要求保持内存增长可控，优先使用压缩或按需结构，不引入大常驻索引。
- 验收：`content:import` 稳定低于 200ms，并能解释每次 phase2 成本。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页或持锁窗口。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier，lockWait 不再出现 50ms+。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，并评估大顺序写的 `F_NOCACHE`/同类策略，减少对搜索热页的冲刷。

### P1：继续为 advanced-linear-gcd 增加轻量剪枝

- 对中文和路径类查询记录扫描记录数、tombstone 跳过数和 segment 分布。
- 评估轻量字符 n-gram、路径分段索引、预过滤位图或 segment-level skip list。
- 验收：`中文测试` 与 `path:/Users` 不再在 160-500ms 区间大幅摆动。

### P1：补充 lockWait 与后台状态关联观测

- 记录每次查询锁等待对应的 flush/update 状态、持锁线程、等待阶段和持锁耗时。
- 验收：确认当前 0ms lockWait 是真实无锁等待，而不是统计粒度不足；解释历史 `content:import` 67.6ms lockWait 来源。
