- 若后续稳定在 1-5 秒则无需关注。

- **0/16 >500ms**——历史首次全部查询达标。
- **P50=27ms，Max=65ms**——全部查询均为内存速度。

## 7. 优化建议

### P2：Compaction 阈值考量

- 当前 25% 阈值——在 page cache 热状态下 tombstone 对性能无影响。
- **建议保持 25%**——过早 compaction 反而会：
  1. 中断 page cache 热状态（新文件内容不在缓存中）
  2. 消耗 I/O 预算
- **compaction 的价值是减少磁盘空间和 flush rewrite 时间**——不是改善查询性能。

### P2：Page cache 预热策略

- 本轮证明 page cache 热状态是最佳性能的关键。
- **方案**：启动后主动 `mmap` 或 `read` 整个索引文件以预热 page cache。
- **预期收益**：避免 R104-R106 的冷启动退化期。

### P3：Flush rewrite 峰值控制

- 32.5 秒峰值虽未影响本轮，但在查询恰好落入该窗口时会造成 GCD 延迟。
- **已知方案**：GCD 队列优先级隔离（仍为最终优化目标）。
