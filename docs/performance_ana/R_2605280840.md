三个查询的 trigramMs 同步偏高，说明是 trigram bucket 页面的缓存命中率整体下降，而非单个查询的特异性问题。`MacEverything` 12ms 接近历史最高（R28 为 7ms，R13 附近高峰期更高）。

可能原因：清晨 8:40 系统活跃度回升，其他进程的 I/O 挤压了 trigram 索引页面的文件系统缓存。注意 phase2Ms 不受影响——phase2 在内存中操作候选列表，不依赖文件缓存。

**关键观察**: trigram 查找偏高的同时，线性扫描反而处于低位——这与预期相反。如果是全局 I/O 压力，线性扫描（需要遍历更多数据）应该更受影响。可能的解释：线性扫描的数据在连续内存区域（SoA 布局），受缓存替换影响较小；而 trigram bucket 分散在索引文件的不同位置，对缓存局部性更敏感。
