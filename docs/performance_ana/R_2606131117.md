## 6. 问题清单

### P0：tombstone 在 13% 以上继续上行

- 证据：tombstone=846,777（13.77%），较上一轮增加 10,604。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：前台本轮恢复不代表根因消失，tombstone/compaction 问题仍在恶化。

### P0：flush 高频且没有退避

- 证据：`FLUSH=742`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=2802ms。
- 影响：即使最新 flush 较上一轮回落，仍是秒级完整重写，并持续制造 page-cache 与 I/O 干扰风险。

### P0：上一轮 foreground 超标暴露的后台交叠风险仍未解除

- 证据：`QUERYADV_GE500=14` 保持；上一轮新增 `.pdf`=1049ms、`main.cpp`=649ms，本轮未复现；latest flush 从 10460ms 降到 2802ms 后 foreground 同步恢复。
- 影响：查询延迟对后台 flush/page-cache 状态高度敏感，用户体验会出现周期性尖刺。

### P1：诊断日志显示中文查询无法走 trigram

- 证据：最新日志末尾 `DIAG-TRIGRAM key="中文测试" SKIP reason=allFound=false ... rawCands=0`。
- 影响：中文类查询仍会落到 `advanced-linear-gcd`，在 page-cache 冷却或 tombstone 上升时容易重新成为尾部。

### P1：pure-filter 与 path 查询仍略高于 50ms

- 证据：`content:import`=56.7ms，`path:/Users`=51.0ms。
- 影响：本轮很轻，但二者历史上多次处在 200-500ms 区间，仍需结构性剪枝与观测。

## 7. 优化建议

### P0：继续优先给 flush 加前台保护和退避

- 当最近 flush 超过阈值时，提高下一次 flush 间隔、降低 batch 频率，或前台查询活跃时推迟大 flush。
- 持久化线程使用低 QoS，并评估大顺序写的 `F_NOCACHE`/同类策略，减少对搜索热页的冲刷。
- 验收：常规 flush 不再与 query battery 同期制造 >500ms 查询；lockWait 不再出现 100ms+。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页或持锁窗口。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 scan/filter 路径继续扫描大量无效记录。
- 验收：tombstone 率从 13%+ 回落，扫描/过滤路径稳定 <200ms。

### P0：拆分 top-level query timing

- 对所有路径增加 queueWait、lockWait、phase2、candidate materialization、path/file metadata load、sort/rank、result assembly、HTTP serialization/write 等阶段耗时。
- 对上一轮 `main.cpp` phase2 低但 top-level 高的案例，必须能解释差值来源。
- 验收：`queryTimeMs - phase2Ms - lockWaitMs` 不再是不可解释的大黑盒。

### P1：为中文与路径查询增加轻量剪枝

- 对中文和路径查询记录扫描记录数、tombstone 跳过数和 segment 分布。
- 评估路径分段索引、轻量字符 n-gram、预过滤位图或 segment-level skip list。
- 验收：`中文测试` 与 `path:/Users` 不再随 page-cache 状态从 50ms 摆动到 500ms。

### P1：细分 trigram/postings 路径

- 对 `advanced-trigram` 记录 postings 读取、候选交并、候选评分、路径加载、结果组装、page-cache miss 近似指标。
- 验收：`.pdf`、`main.cpp` 在 flush 后仍稳定 <100ms，或至少能解释冷启动成本。
