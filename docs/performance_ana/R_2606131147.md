## 6. 问题清单

### P0：tombstone 逼近 14% 且继续快速上行

- 证据：tombstone=861,957（13.98%），较上一轮增加 15,180。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：13% 以上已经持续多轮，本轮接近 14%，compaction/清理策略明显偏晚。

### P0：scan/filter 路径从恢复态重新退化

- 证据：扫描/过滤路径总和从 181.9ms 升至 1130.9ms；`中文测试`=439.0ms、`content:import`=349.8ms、`path:/Users`=263.4ms。
- 影响：虽然没有超过 500ms，但 P90 已升到约 349.8ms，用户会感知到周期性卡顿。
- 判断：主要耗时均在 phase2，lockWait=0ms，说明根因仍是扫描量、tombstone、page-cache 冷却或缺少剪枝。

### P0：flush 高频且没有退避

- 证据：`FLUSH=754`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=5160ms。
- 影响：完整重写继续以半小时约 +12 次的节奏增长，并持续制造 I/O 与 page-cache 干扰风险。

### P0：最新常规 flush 回到 5 秒级

- 证据：最新 flush total 从 2802ms 升至 5160ms，增长 84%。
- 影响：即使没有新增 >500ms 日志级慢查询，5 秒级重写仍足以冲刷搜索热页，让 scan/filter 查询在下一轮或同轮变慢。

### P1：中文查询仍依赖 linear-gcd

- 证据：`中文测试` 走 `advanced-linear-gcd`，queryTimeMs=439.0ms、phase2Ms=437.3ms；latest log total=438ms。
- 影响：中文类查询无法获得 trigram/postings 的候选剪枝收益，在 tombstone 上行和 page-cache 冷却时容易成为尾部。

### P1：top-level 非 phase2 成本仍缺少解释

- 证据：`MacEverything` queryTimeMs=56.3ms、phase2Ms=3.4ms；`content:import` queryTimeMs=349.8ms、phase2Ms=328.9ms，仍有约 20ms 差值。
- 影响：现有 timing 仍无法完整解释结果加载、排序/组装、HTTP 写出、队列等待或 page-cache miss 成本。

## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 scan/filter 路径继续扫描大量无效记录。
- 验收：tombstone 率从 13.98% 回落，`中文测试`、`content:import`、`path:/Users` 稳定 <200-300ms。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页或持锁窗口。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier，`SKIPFLUSH` 不再长期为 0。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔、降低 batch 频率，或前台查询活跃时推迟大 flush。
- 持久化线程使用低 QoS，并评估大顺序写的 `F_NOCACHE`/同类策略，减少对搜索热页的冲刷。
- 验收：5s+ flush 后 query battery 不再把 scan/filter 推到 300-500ms 区间。

### P0：为 advanced-linear-gcd 与 pure-filter 增加轻量剪枝

- 对中文、路径、content/filter 类查询记录扫描记录数、tombstone 跳过数和 segment 分布。
- 评估轻量字符 n-gram、路径分段索引、预过滤位图或 segment-level skip list，以减少无结果或低选择性查询的全量扫描。
- 要求保持内存增长可控，优先使用压缩或按需结构，不引入大常驻索引。
- 验收：`中文测试` 不再接近 500ms，`content:import` 和 `path:/Users` 稳定低于 200ms。

### P1：拆分 top-level query timing

- 对所有路径增加 queueWait、phase2、candidate materialization、path/file metadata load、sort/rank、result assembly、HTTP serialization/write 等阶段耗时。
- 对 `MacEverything` 这类 phase2 低但 top-level 高的案例，必须能解释差值来源。
- 验收：`queryTimeMs - phase2Ms - lockWaitMs` 不再是不可解释的大黑盒。

### P1：细分 trigram/postings 路径

- 对 `advanced-trigram` 记录 postings 读取、候选交并、候选评分、路径加载、结果组装、page-cache miss 近似指标。
- 验收：`.pdf`、`main.cpp` 在 flush 后仍稳定 <100ms，或至少能解释冷启动成本。
