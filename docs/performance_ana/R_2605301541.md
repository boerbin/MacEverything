## 4. ns/槽：本轮不可信（争用对数值路径打击更重，制造假象）

- `dm:today` 沉降中位 **194ms** → 若按此计 ns/槽 = 194×1e6/5.92M = **32.8**

数值层 dm（32.8）已逼近字符串层 content（35.8），二者间隙被争用压缩到几乎重叠。**若机械地采用这组数据，会得出「二层分裂破裂」的假性结论**——但这纯属写锁争用对随机路径的不均匀打击（本轮恰好数值路径排在摄入突发期），**非机制变化**。按「不要轻易下结论、每个结论需逻辑+数据支撑」，本轮 ns/槽与分裂判定**一律挂起**。

## 10. 优化建议（强化 P0 写锁争用维度）

1. **🔥 P0｜R67 flush 检查顺序修复**：调换 `:142`/`:159` + 阈值下调 <12.97%（建议 8–10%）。当前 8.87%（实时 9.02%）已在建议区间内、且本轮摄入加速推高，紧迫性最高。
2. **🔥 P0｜无锁快照 flush / 读写锁分离（本轮强化升级）**：本轮**首次实证**自身摄入持索引写锁会饿死读查询（`*.swift` lockHeld=1290ms 占满 total）。启动 flush 持锁 10.3s 是同一锁争用类问题。**应引入读写分离**——读查询走不可变快照、写入走 copy-on-write 或双缓冲，使摄入期间读路径不被阻塞。这是本轮新证据直接指向的最高价值修复。
3. **🔥 P0｜查询超时保护 + 降级返回**：R88-R90（1663/1002/861ms 外部）+ **R95（1290ms 自身摄入争用）**——超时熔断在「自身摄入」场景同样必要，避免单查询被写锁阻塞 >1s。
4. **🔥 P0｜mlock/madvise 整体常驻热区**：对外部停顿仍有效；但本轮争用源自锁而非页换出，本项对 R95 类争用作用有限——**优先级让位于第 2 项读写分离**。
- **P0｜HTTP 并发**：acceptLoop 单线程，摄入争用期间串行阻塞放大影响。
- **P1🔥｜CJK trigram 索引**：`中文测试` 走 linear-gcd 全扫（本轮受争用最重，多次 >500ms）。

## 11. 结论

- **定性**：⚠️ 活跃后台摄入轮——会话内**首个自身写锁争用污染轮**。三条独立证据（live +3476 暴涨、日志 totalRecords 窗口内增长、`*.swift` lockHeld=1290≈total）共指 MacEverything 自身后台索引写入持锁饿死读查询，与 R88-R94 的外部系统停顿**本质不同**。
- **诚实修正纪律（本轮核心）**：①ns/槽**拒绝给出**——争用把数值路径（dm 沉降中位 194ms→32.8 ns/槽）抬进字符串区间（content 35.8），机械采用会得出假性「分裂破裂」；②二层分裂判定**挂起**，战绩保持 21/21 不增不减，待下一洁净轮恢复检验；③测量校正——20765/10353ms 是启动 Phase-2 replay 与 flush 非查询，>5s 段仍冻结于 7。**没有洁净数据就不强行下结论**。
- **新观察（明确边界）**：自 R90 以来首次在日志层新增 >500ms 查询（1-5s 23→24、0.5-1s 16→22），打破 5 轮冻结，但全部止于 1.3s、未触历史天花板；`saf` 用户查询 579ms 证明争用波及真实流量。复测反复突发、30s 沉降后仍噪声，证明摄入引发的锁争用是周期性反复、非一次性消退。
- **唯一可靠恶化项**：tombstone **525,387 / 8.87%**（连续 28 轮单调，实时读已破 9.02%），本轮增量 +21,579 显著放大，~86% 新增记录直接变 tombstone，根因 R67 阀门结构性不可达明确。摄入加速使修复紧迫性进一步上升。
- **最高价值修复指向**：本轮新证据把 **P0 #2 升级为「读写锁分离 / 无锁快照读」**——这是唯一直接针对本轮根因（写锁饿死读）的修复，优先级高于 mlock。
