## 6. 问题清单

### P0：前台发生严重系统性慢查询

- 证据：5/16 top-level query >500ms，`hello world`=3804.5ms。
- 影响：用户交互搜索出现 0.5-3.8 秒级等待，已明显不可接受。
- 判断：trigram、ext-index、linear-gcd 多路径同时受影响，不是单 query 异常。

### P0：trigram/postings 热区严重冷却

- 证据：`.pdf`=536.5ms，`hello world`=3804.5ms，`abc def...`=393.0ms，`*.swift`=202.1ms。
- 影响：常见文件名搜索直接退化到用户可感知卡顿。

### P0：后台 flush 常规成本升至 5-6 秒级

- 证据：最新 flush total=5798ms，rewrite=5461ms，sqcache=325ms。
- 影响：即使排除 38 分钟 outlier，常规 flush 也足以干扰前台搜索热数据。

### P0：38 分钟级 flush outlier 仍是 latest session 最大风险

- 证据：`rewrite=2285476ms`、`total=2285536ms`。
- 影响：后台持久化长时间占用 I/O，造成 page-cache 污染和搜索热区反复冷却。

### P0：tombstone 继续高于 9%

- 证据：tombstone=544,396（9.35%），较上一轮增加 8,478。
- 影响：索引体积、flush rewrite 成本和扫描成本继续扩大。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 9%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对搜索热区使用 `madvise` 预热/保持。
