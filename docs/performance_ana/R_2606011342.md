## 9. 可能问题定位

### P0-1：rewrite cluster 导致 page residency 长时间不稳定

证据：

- 本轮新增 14 次 ≥5s rewrite，包含 `36,995ms`、`12,637ms` 两次长 rewrite。
- 与上一轮相比，`content/path/中文` reprobe floor 分别从 `50.30/45.06/43.50ms` 退化到 `101.12/99.17/124.61ms`。
- 查询日志未新增 ≥500ms，但 API 样本出现 `path:/Users=322.62ms`、`中文测试=330.72ms`、`content:import=313.22ms`。

根因判断：page-cache 或 mmap residency 没有在 probe 期间恢复到上一轮热态，full-scan 所需的字符串/路径/content 页持续处于较冷状态。

### P0-2：full-scan 成本仍在锁内执行

证据：

- `content:import total=173.26ms / phase2=166.86ms / lockHeld=166.86ms`。
- `path:/Users total=166.59ms / phase2=161.97ms / lockHeld=161.97ms`。
- `中文测试 total=180.19ms / phase2=180.06ms / lockHeld=180.17ms`。

根因判断：只要 page residency 变差，扫描成本会直接变成锁持有时间。当前没有超过 500ms 只是程度问题，不是架构风险消失。

### P0-3：runtime reclaim 阀门仍未介入，tombstone ratio 达 23.59%

证据：

- `tombstoneRatio=23.59%`。
- `COMPACTION=2 / RECLAIM=0`。
- 本轮 tombstones 增加 `24,877`，live records 只增加 `3,408`。

根因判断：25% reclaim valve 对当前负载太迟。系统已经在 23%+ tombstones 下经历明显 rewrite 和 scan floor 问题，但回收仍未触发。

### P1：数值/日期列也受到扰动，不只是字符串列

证据：

- `size` floor 从上一轮 `3.62ms` 退化到 `13.25ms`。
- `dm` floor 从上一轮 `12.62ms` 退化到 `43.95ms`。

根因判断：本轮 page/cache 扰动不只影响 path/content/中文，基础数值列也受影响；但字符串/路径列仍是绝对高位。

## 10. 优化建议

### P0：增加 rewrite density guard，限制连续长 rewrite 对查询页的扰动

- 当短窗口内出现多个 ≥5s rewrite，尤其是 ≥10s rewrite 或 ≥30s rewrite 时，应合并、推迟或降频后续 rewrite。
- 本轮 `13:17–13:43` 内新增 14 次 ≥5s rewrite，并伴随 full-scan floor 回升。
- 验收标准：`FLUSH_GE5` 增速下降，连续长 rewrite 后的 `content/path/中文` W1 与 reprobe floor 不再明显抬升。

### P0：rewrite 后 targeted prewarm content/path/string 页

- 对 content/path/trigram 字符串页进行轻量预热，或使用 `madvise(WILLNEED)` 提示关键 mmap 区域。
- 不建议全量常驻内存；目标是降低 rewrite 后第一批 full-scan query 的冷页成本。
- 验收标准：`content/path/中文` W1 不再从热态 40–50ms 抬升到 170–330ms。

### P0：降低 runtime reclaim threshold，或改为 debt-based 复合触发

- 当前 `tombstoneRatio=23.59%` 已造成 rewrite 和 full-scan floor 风险，但 `RECLAIM=0`。
- 建议将阀值从 25% 降到 8–10%，或按 `tombstone ratio + absolute tombstones + rewrite density` 触发 reclaim。
- 验收标准：`RECLAIM>0`，tombstone ratio 回落到 10% 以下，full-scan floor 与 rewrite 时长不再随 tombstone 单调恶化。

### P0：读写解耦，避免锁内承担 page fault / full-scan

- 查询使用不可变 snapshot；flush/rewrite 通过 pointer swap 发布新版本。
- 优先处理 `advanced-pure-filter-soa-gcd` 与 `advanced-linear-gcd`，因为它们的 `lockHeld≈phase2≈total`。
- 验收标准：当 `path/content/中文` 出现 300ms 样本时，`lockHeldMs / totalMs` 不再接近 1。

### P1：增加 page-residency 观测与列级 scan 指标

- 记录每类 full-scan 的列访问、字符串 dereference、慢页估计、跳过数、编码匹配耗时。
- 同时记录 rewrite 完成后的首 N 次 query 的 cold/warm 差距。
- 验收标准：能解释本轮 `size/dm/content/path/中文` 同步退化的原因，并能把 rewrite cluster 与 query floor 变化关联起来。

## 11. 结论

本轮没有新增 ≥500ms 慢查询日志，但这不是好转信号：`FLUSH_GE5` 单轮增加 14 次、`FLUSH_GE10` 增至 25、tombstone ratio 到 `23.59%` 且 `RECLAIM=0`。同时 full-scan reprobe floor 从上一轮热态的 `43–50ms` 回升到 `99–125ms`，说明 rewrite/page-cache 扰动正在让 page residency 长时间不稳定。建议优先实施 rewrite density guard、targeted prewarm、降低 reclaim 阀值和读写解耦；否则随着 tombstone ratio 逼近 25%，下一轮很可能重新出现 ≥500ms 的 path/content/中文慢查询。
