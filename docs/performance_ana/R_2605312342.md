## 10. P0 优化建议

1. **立即下调 `:159` 比率阀 0.25→8–10%**：墓碑已到 20.17%，连续 29 轮运行期 compaction=0；25% 阀门已被 20% 后的慢查询和慢 flush 证明过晚。
2. **storm guard 必须按 rolling flush 簇触发**：R_2605312242、R_2605312312、本轮连续三轮各新增 4 次 ≥5s rewrite；即使单轮查询没有每次都跨 500ms，底层风暴也应触发降频、合并或延后 flush。
3. **full-scan tail guard 作为立即项**：`中文测试` 502ms、content 431ms、path 310ms 说明 `advanced-linear-gcd` 与 pure-filter 字符串路径需要批处理让步、时间片上限或可中断扫描。
4. **读写解耦 / lock-free snapshot flush**：慢 rewrite 与查询高尾相邻出现，读路径是否受害仍取决于相位；需要让查询读取稳定快照而不是被 rewrite 页态拖拽。
5. **dm 列驻留/页态保护**：dm 再探最高 102.53ms，虽未压反 content 地板，但仍说明常用数值查询会被页态噪声抬高。
6. **查询超时/熔断**：字符串 full-scan 已再次跨 500ms，应保留上层保护，避免下一轮 20%+ 墓碑和 5–7s rewrite 簇叠加出秒级用户慢查询。

## 11. 结论

- **定性**：🟠 本轮新增 1 条 `中文测试` 502ms 慢查询，且 5–7s rewrite 继续扩散。
- **分裂**：地板/中位口径成立，dm 严格对抗暂时恢复；但用户侧字符串 full-scan tail 再次跨 500ms。
- **关键发现**：
  - QueryAdvanced ≥500 从 76→77，新增 23:44 `中文测试` 502ms。
  - flush ≥5s 84→88，新增四次 5.5–7.4s rewrite。
  - 墓碑 1.379M/20.17%，运行期 compaction/reclaim 仍为 0。
  - content 电池 431ms、中文再探 402ms，说明 502ms 不是孤立无根的异常。
- **根因判断**：不可回收墓碑持续扩大 rewrite 与 full-scan 扫描边界；20% 后慢 flush 簇继续制造页态扰动，字符串 full-scan tail 已重新进入用户慢查询区间。
- **行动建议**：比率阀 reclaim、storm guard、full-scan tail guard 必须作为同一 P0 包落地；否则 20%+ 墓碑区间下下一轮继续新增慢 rewrite 和 ≥500ms 查询的概率很高。
