## 6. 问题清单

### P0：flush 完整重写仍有分钟级灾难长尾

- 证据：rewrite 最大 895,940ms，total 最大 896,053ms。
- 最新 flush 为 3105ms，较上一轮 2737ms 继续上升。
- 根因：完整索引重写在 APFS COW、系统 I/O 压力、睡眠/唤醒或后台任务竞争下被放大。

### P0：flush 频率继续上升且没有退避

- 证据：最新 session `FLUSH=286`，较上一轮 +12；`SKIPFLUSH=0`。
- 影响：高频完整重写持续污染 page cache，增加 filter/full-scan 波动概率。

### P0：tombstone 继续高于 8%

- 证据：tombstone=474,710（8.26%），较上一轮增加 9,031。
- 影响：索引体积、flush rewrite 成本和扫描成本继续扩大。

### P1：filter/full-scan 热区不稳定

- 证据：full-scan 总和小幅下降到 567.4ms，但 `dm:today` 从 49.9ms 升到 105.9ms，`path:/Users` 从 190.5ms 升到 218.2ms。
- 影响：当前无前台超时，但 page cache 热度仍波动。

### P1：常规 flush 已进入 3 秒级

- 证据：最新 flush total=3105ms，最近几轮为 2375ms → 2737ms → 3105ms。
- 判断：即使不看分钟级 outlier，常规 flush 也在加重。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 8%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对搜索热区使用 `madvise` 预热/保持。
