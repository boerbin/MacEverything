## 6. 问题清单

### P0：tombstone 继续逼近 12%

- 证据：tombstone=714,207（11.89%），较上一轮增加 6,152。
- 影响：无效记录比例继续升高，会放大扫描、flush rewrite 与后续 compaction 成本。
- 判断：虽然前台查询本轮改善，但 tombstone 趋势没有改善，属于后台结构性风险。

### P0：flush 高频且没有退避

- 证据：`FLUSH=550`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=3701ms。
- 影响：秒级完整重写持续发生，会污染 page cache，并在 I/O 压力下放大为分钟级 outlier。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径在压力下缺少有效切分和退避，前台偶发长尾仍可能复现。

### P1：扫描类路径仍是前台尾部主因

- 证据：`path:/Users`=288.4ms，`中文测试`=244.2ms，`content:import`=228.8ms；full-scan 总和=877.7ms，较上一轮略升。
- 影响：本轮没有突破 500ms，但扫描路径仍明显高于 indexed/trigram 热路径。

### P1：top-level 与 phase2 差值仍需要拆分

- 证据：例如 `path:/Users` top-level 288.4ms、phase2 277.6ms，差值约 10.8ms；`content:import` 差值约 9.8ms。
- 影响：当前能确认 phase2 是主耗时，但非 phase2 部分仍缺少细分，难以判断结果组装、排序、HTTP 序列化或锁外等待的占比。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放入后台低优先级任务，不与前台查询争抢热页。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，避免冲掉搜索路径 page cache。

### P0：提前或分段 compaction

- 不等待高全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 验收：tombstone 率从 11.89% 回落，full-scan 总和和常规 flush rewrite 同步下降。

### P0：降低 flush 频率并合并 WAL 批次

- 设置最小 flush 间隔和最大合并窗口。
- 对高 churn 目录减少完整重写次数，避免 `FLUSH` 计数持续快速增长。

### P1：拆分扫描路径耗时

- 对 `advanced-linear-gcd`、`advanced-pure-filter-soa-gcd` 记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 验收：能明确 `path:/Users`、`中文测试`、`content:import` 的主要瓶颈是扫描量、tombstone、排序还是 page-cache 冷却。

### P1：补充非 phase2 耗时与后台状态关联

- 在查询日志中记录 phase1、phase2、结果组装、HTTP 序列化、lockWait 以及当前 flush/update 状态。
- 验收：能够解释 top-level 与 phase2 差值，并判断后台 flush 是否与前台尾延迟同周期出现。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用预热或访问提示，减少 flush 后冷启动波动。
