## 5. 主要问题

1. **flush 风暴**：flush 平均间隔只有 42s，远低于 initial interval=300s。IndexPersistence/FlatIndexWriter 占日志主体，写盘调度过密。
2. **tombstone 走势需要关注**：tombstone 占比从 6.2% 到 3.5%。如果 compaction 已生效，需要补充完成日志；如果未生效，线性查询会继续变慢。
3. **paged index flush ERROR 缺少现场**：ERROR 只有兜底文案，没有 errno、path、stage、free space，无法定位根因。
4. **查询时延强抖动**：冷态多数查询是个位数到百毫秒，但重复采样中 `a/.h/.md` 可到秒级，疑似与 flush 抢锁有关。
5. **括号字面量不可搜**：`test (1)`、`test(1)`、`(test)` 返回 0，影响 macOS 自动重命名文件。
6. **AI 翻译存在错误输出**：`图片 -> pic:` 仍是残缺语法，AI 统计为 n=269, min=278ms, avg=445ms, median=394ms, p95=683ms, max=1420ms。
7. **内容索引为空**：contentIndexedFileCount=0，内容搜索相关能力不可用或未初始化。

## 6. 优化建议

| 优先级 | 建议 | 预期收益 |
|---|---|---|
| P0 | 对 flush 增加硬限流和 debounce，事件触发也必须 coalesce 到 300s 级别 | 降低写放大，减少查询锁等待 |
| P0 | `Failed to flush paged index` 增加 errno/path/stage/freeBytes 日志 | 下次能定位根因 |
| P0 | 墓碑比例超过 15% 触发 compaction，并记录开始/完成/耗时/前后记录数 | 控制索引膨胀 |
| P0 | QueryParser 在普通查询中把括号作为字面量处理 | 修复 `xxx (1)` 类文件不可搜 |
| P1 | 为扩展名维护倒排索引 `ext -> recordIds` | `.h/.md/.cpp` 从 O(N) 降到近似 O(k) |
| P1 | 查询路径和 flush 路径使用 shared/read-write lock 或 RCU 快照 | 消除秒级抖动 |
| P1 | HTTP 访问日志记录 path/query/latency/results | 提升线上定位效率 |
| P1 | 精简 AI prompt，修正 `图片 -> pic:`、`cpp文件 -> content:cpp` 样例 | 降低 p95，提高翻译质量 |

## 7. 结论

当前服务可用，但后台健康度仍不稳定。核心风险是 flush 过密、错误日志不可定位、括号查询语义错误，以及内容索引长期为空。建议先修 P0 四项：flush 限流、ERROR 现场、compaction 观测与触发、括号字面量。
