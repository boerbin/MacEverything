## 6. 问题清单

### Critical：系统性 I/O 压力导致全面性能崩溃

- **证据**：
  1. 13/16 查询超过 500ms，退化倍数 5x-22x。
  2. 所有搜索路径（trigram、ext-index、linear-gcd、pure-filter、cache）均受影响。
  3. lockWaitMs 在 4 个查询上出现（`main.cpp`=583ms 为历史最高）。
  4. phase2 耗时暴涨：`.pdf` phase2=9382ms（正常 ~80-300ms）。
- **根因判断**：
  - 非 tombstone 导致（3.29% 额外扫描不会导致 22x 退化）。
  - 非锁竞争导致（lockWaitMs 仅在少数查询出现，且多数退化查询 lockWait=0）。
  - **系统级 I/O 压力**：macOS 文件系统缓存被挤出或磁盘 I/O 队列饱和，导致所有涉及磁盘访问的操作均大幅变慢。
  - 可能触发因素：Time Machine 备份、Spotlight 索引重建、大规模文件操作、或其他进程的密集 I/O。
- **预计为暂态事件**——下一轮如 I/O 压力缓解将恢复正常。

### Critical：tombstone 逼近 3.5%（3.29%，195,128 条）

- 增长轨迹：
  ```
  R63: 158K (2.69%) → R64: 160K (2.71%) → R65: 169K (2.87%)
  → R66: 185K (3.13%) → R67: 195K (3.29%)
  ```
- 本轮增量 9,914 条。
- **累计内存开销**：~195K × 300 字节 ≈ 59MB。
- SKIPFLUSH=144，compaction 仍完全不可触发。

### High：lockWaitMs 首次批量出现

- `main.cpp`=582.5ms、`*.swift`=4.0ms、`hello world`=1.9ms、`README`=1.5ms、`MacEverything`=0.4ms。
- 此前 lockWaitMs 仅在个别查询偶现（R54=223ms、R58=4.8ms）。
- 本轮 5 个查询同时出现 lockWait，表明 I/O 压力期间写锁持有时间延长。
