## 6. 问题清单

### P0：flush 完整重写导致分钟级长尾

- 证据：rewrite 最大 895,940ms，total 最大 896,053ms。
- 影响：flush 期间可能长时间占用 I/O 和内部写锁，造成前台查询抖动、page cache 冲刷、服务响应长尾。
- 根因：当前 flush 仍是完整索引重写，而不是增量/COW 页写入。

### P0：flush 节奏过密且缺少退避

- 证据：最新 session `FLUSH=202`，`SKIPFLUSH=0`。
- 影响：持续重写大文件，持续污染 page cache，和搜索热数据抢 I/O。
- 根因：WAL flush 触发机制只看待刷条件，缺少 I/O 压力感知、退避和前台保护。

### P0：tombstone 快速增长

- 证据：tombstone=402,511（7.11%），较 R271 的 3.38% 大幅上升。
- 影响：索引体积和扫描成本继续上升，flush rewrite 负担增加。
- 根因：路径更新/删除产生大量旧 record，compaction 触发仍不够及时。

### P1：compaction 触发仍不足

- 证据：最新 session `COMPACTION=2`，但 tombstone 仍升至 7.11%。
- 影响：系统尚未进入 25% 阈值，但绝对 tombstone 已超过 40 万，正在放大 flush 和扫描成本。

## 7. 优化建议

### P0：将 flush 从完整重写改为增量/COW 页写入

- 目标：将常规 flush 从秒级/分钟级降到 <100ms 级别。
- 做法：分离 stable segment 与 delta segment；flush 只追加 delta pages，后台低优先级合并。
- 验收：最新 session 中 rewrite max 不超过 200ms；battery 后无 >500ms 慢查询新增。

### P0：为 flush 增加 I/O 压力退避与前台保护

- 检测当前是否有前台查询、系统是否 I/O 饱和、上次 flush 是否超时。
- 若 flush 超过阈值，下一轮延迟或降低写入批量。
- 对搜索线程设置更高 QoS，对持久化线程设置 utility/background QoS。

### P0：降低 flush 频率并合并 WAL 批次

- 当前最新 session `FLUSH=202`，过于频繁。
- 建议引入最小 flush 间隔、最大合并窗口、后台 idle flush。
- 目标：在不牺牲崩溃恢复语义的前提下减少大文件重写次数。

### P1：提前 compaction 或 segment-level compaction

- tombstone 已达 7.11%，虽然低于 25%，但绝对数量已经影响 flush 成本。
- 建议采用分段 compaction，而不是等待全局 25% 阈值。

### P2：madvise / fcntl_nocache 热区保护

- 对搜索热数据保持 page cache。
- 对 flush 大顺序写尽量避免污染 cache。
