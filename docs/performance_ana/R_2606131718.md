## 7. 优化建议

### P0：为 full-index flush 增加硬性前台保护与退避

- 对 flush rewrite 超过 2s/5s/8s 建立分级退避：延后下一次 flush、降低 batch 频率、前台查询活跃时禁止大 rewrite。
- 持久化线程使用低 QoS，并评估大顺序写的 `F_NOCACHE`/同类策略，减少对搜索热页的冲刷。
- 在日志中记录触发/跳过 flush 的原因，避免 `SKIPFLUSH=0` 长期无法解释。
- 验收：9s 级 flush 不再出现；出现 5s+ flush 后下一周期必须看到 backoff 或 skip 证据。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页或持锁窗口。
- 验收：常规 flush total <200ms，新 session 不再出现 3-9s 级完整 rewrite。

### P0：立即提前或分段 compaction

- 以 tombstone 率 14%+ 或绝对 tombstone 900k+ 作为明确触发信号；当前 15.11% 已超过应急阈值。
- 结合 segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 scan/filter 与 flush rewrite 继续放大。
- 验收：tombstone 率从 15.11% 回落，`中文测试`、`path:/Users`、`content:import` 稳定 <200ms。

### P0：为 advanced-linear-gcd 与 pure-filter 增加轻量剪枝

- 对中文、路径、content/filter 类查询记录扫描记录数、tombstone 跳过数和 segment 分布。
- 评估轻量字符 n-gram、路径分段索引、预过滤位图或 segment-level skip list，以减少无结果或低选择性查询的全量扫描。
- 要求保持内存增长可控，优先使用压缩或按需结构，不引入大常驻索引。
- 验收：`中文测试` 与 `path:/Users` 稳定低于 200ms，`content:import` 不再维持 100ms+。

### P1：细分 trigram/postings 路径

- 对 `advanced-trigram` 记录 postings 读取、候选交并、候选评分、路径加载、结果组装、page-cache miss 近似指标。
- 重点解释 16:48 的 `hello world` 223.1ms 与本轮 47.2ms 的差异。
- 验收：trigram 查询在 5s+ flush 后仍稳定 <100ms，或至少能解释每个阶段的成本。

### P1：细分 scan/filter 与 top-level timing

- 对 pure-filter 和 linear-gcd 记录扫描记录数、跳过 tombstone 数、命中 live 数、segment 数、metadata 加载耗时和结果组装耗时。
- 对所有路径增加 queueWait、phase2、candidate materialization、path/file metadata load、sort/rank、HTTP serialization/write 等阶段耗时。
- 验收：`queryTimeMs - phase2Ms - lockWaitMs` 不再是不可解释的大黑盒。
