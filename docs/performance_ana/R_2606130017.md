## 6. 问题清单

### P0：tombstone 已突破 11%

- 证据：tombstone=659,724（11.09%），较上一轮增加 9,604。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。
- 判断：tombstone 已从 10% 风险区进入 11% 区间，继续等待高全局阈值会让后台完整重写和前台扫描长尾继续恶化。

### P0：扫描类前台尾延迟明显恶化

- 证据：`content:import`=350.5ms，`path:/Users`=279.5ms，`中文测试`=411.8ms，full-scan 总和=1041.8ms。
- 影响：虽然尚未超过 500ms，但 `中文测试` 已接近阈值，下一轮在 I/O 压力稍增时很可能突破 500ms。

### P0：flush 高频且没有退避

- 证据：`FLUSH=478`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=3212ms。
- 影响：秒级完整重写持续污染 page cache，是前台冷热波动的主要背景风险。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，19:06 flush total=107,008ms。
- 影响：持久化路径在 I/O 压力下可被极端放大，前台查询当前未超标不代表根因消失。

### P1：非 phase2/top-level 耗时再次出现

- 证据：`MacEverything` queryTimeMs=66.5ms，但 phase2Ms=1.2ms。
- 影响：部分查询耗时来自 phase2 之外，仍需拆分 HTTP handler、结果组装、排序和 JSON 序列化耗时。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 11% 回落，并且常规 flush rewrite 时间下降。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：拆分扫描路径与非 phase2 阶段耗时

- 对 `advanced-linear-gcd`、`advanced-pure-filter-soa-gcd` 记录扫描记录数、过滤命中数、排序/组装耗时。
- 对 HTTP handler、结果 materialization、JSON 序列化分别打点。
- 验收：能区分 tombstone/扫描成本、结果组装，还是 page-cache 冷却导致的波动。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA 热区使用 `madvise` 预热/保持。
