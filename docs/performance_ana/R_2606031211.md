## 6. 问题清单

### High：tombstone 首次突破 1% 阈值

- 证据：六轮 tombstone 增长轨迹 4,118 → 6,236 → 17,015 → 33,512 → 44,758 → **58,558**。
- 占比从 0.07% 增长至 1.01%，增速持续加快（本轮增量 13,800 条）。
- 按当前速率，约 30-50 轮后可能达到影响性能的水平。

### Medium：首次出现显著 lockWaitMs（223ms）

- 证据：`test` 查询 509ms，其中 lockWaitMs=223ms，phase2Ms=282ms。
- 这意味着查询等待写锁释放消耗了 43% 的总时间。
- 可能与后台 FSWatcher 批量更新或 tombstone 增长导致写入增多有关。

### Medium：`.pdf` 查询波动仍存在（229ms → 313ms）

- 六轮范围 208-9221ms，本轮 313ms 属正常波动区间。
- 结构性根因（trigram 候选 ~9934）未变。

### Low：SKIPFLUSH 增速加快（+6/轮）

- 17 → 23，WAL 条目稳定在 68 条（低于 100 阈值）。
- 表明文件系统变动率较低，属正常行为。

### Low：API 响应格式变更（`meta` → 顶层 `timing`）

- `meta` 对象现为空 `{}`，queryTimeMs 移至顶层，详细 timing 移至 `timing` 对象。
- 对 API 消费者是 breaking change，但对内部性能无影响。
- 新增字段：`lockWaitMs`、`lockHeldMs`、`trigramMs`、`candidates`、`nameMatches`、`pathMatches`、`usedTrigram`。
