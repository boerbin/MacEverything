> 诚实声明：无法在"内容压缩"与"WAL 插入批"之间确证 README 锁源——这正是 **P1🔥 lock hold duration 日志**反复被列为必需的原因：它是区分两个候选的唯一手段。

## 4. 退化模型再确认（R62 双信号）

R62 同时呈现两种模式的微缩样本，巩固 R61 的两模式框架：

```
文件系统活动（tombstone +9,861 本区间）
   ├─模式 A（缓存驱逐）：*.swift phase2=1100ms，lock=0  ← 残留冷缓存
   └─模式 B（写侧锁）：README lock=599ms，phase2=28ms   ← 瞬态微锁
```

- 模式 A **可自愈**（R61→R62 多数恢复），但大工作集查询（`*.swift`）自愈慢；
- 模式 B **可微缩出现**（README 599ms），源自瞬态写活动，与 R58 持续爆发同源异量。
- 两者印证核心论断：**退化由查询时刻的瞬时状态（页温度 / 锁占用）决定**，与平均 tombstone 增速无关（R62 增速 19.7K/h 低于 R61，却仍出现两信号）。
