## 10. P0 优化建议

1. **`:159` 比率阀下调 0.25→8–10%**（连续 13 轮唯一阻断点）：墓碑 1,129,708 / 17.18%，入墓比 97.9%。当前证据更强：即使没有新增风暴，基线仍重新硬化，说明只等 OS 页缓存自行恢复不可靠。
2. **mlock/madvise 优先钉住 dm 列**：R122 是最强 dm 证据——再探 6/6 全高位，且无 storm 干扰。dm 列约 6.58M × 8B ≈ 52.6MB，内存成本明确且低于字符串池，收益直接对准对抗口径。
3. **lock-free snapshot flush**：虽然本轮无 ≥5s flush，但每 150s 的 2.8–3.5s rewrite 仍会周期性扫写 6.58M slots。解耦读写是防止下一次页态退化再次放大的根因修复。
4. **读写锁分离**。
5. **查询超时/熔断**。

## 11. 结论

- **定性**：静默期 dm 硬化。无新增 ≥5s flush、无新增 ≥500ms 查询，但 dm 再探 6/6 全高位，说明高位已脱离单次风暴，成为安静期基线。
- **分裂**：**47/47**（全局地板口径 2.91×，对抗 1.10× 贴线）。过去四轮三次对抗落在 1.06–1.10，裕度极窄。
- **关键发现**：
  - R121 的部分恢复未延续：content 114→141ms，path 108→154ms；dm 57–76 混合态 → 78–110 全高位。
  - main.cpp/MacEverything trigram 抬头经再探回落，判定为瞬时页态抖动，不是 trigram 结构性退化。
  - 连续两轮无新增 ≥5s flush 但基线未恢复，证明问题已进入墓碑压力驱动的高压常态。
- **优先级**：先降比率阀阻止墓碑继续累积；同时用约 53MB 成本 mlock dm 列，保护最先失守的数值列。两者是本轮证据直接支持的最小根因修复组合。
