## 6. 问题清单

### P0：tombstone 继续升高到 10.61%

- 证据：tombstone=627,470（10.61%），较上一轮增加 11,404。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。
- 判断：tombstone 已连续多轮高于 10%，继续等待全局高阈值会放大持久化和扫描长尾。

### P0：flush 高频且无退避

- 证据：`FLUSH=442`，较上一轮 +12；`SKIPFLUSH=0`。
- 影响：完整重写持续发生，即使最新一次只有 2.5 秒，仍会周期性污染 page cache。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，19:06 flush total=107,008ms。
- 影响：持久化路径在 I/O 压力下可被极端放大，前台性能波动根因仍未消除。

### P1：full-scan 总和仍在 750ms 级别

- 证据：`content:import`=289.3ms，`path:/Users`=186.6ms，`中文测试`=280.6ms，full-scan 总和=756.5ms。
- 影响：未超标，但 pure-filter/linear-gcd 热区没有恢复到低位，仍容易在 I/O 压力下突破 500ms。

### P1：部分 top-level 查询时间偏高但 phase2 不高

- 证据：`MacEverything` queryTimeMs=166.3ms，但 phase2Ms=1.1ms。
- 影响：瓶颈不在 phase2 搜索本体，可能来自结果组装、排序、JSON 序列化或请求路径的非 phase2 阶段。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 10%+ 回落，并且常规 flush rewrite 时间下降。

### P1：拆分非 phase2 耗时观测

- 对 HTTP handler、结果排序、路径 materialization、JSON 序列化分别打点。
- 优先定位 `MacEverything` 这类 phase2 很低但 top-level 偏高的查询。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA 热区使用 `madvise` 预热/保持。
