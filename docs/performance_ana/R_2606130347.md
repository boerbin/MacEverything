## 6. 问题清单

### P0：tombstone 已贴近 12% 警戒线

- 证据：tombstone=720,459（11.98%），较上一轮增加 6,252。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：前台查询短期改善不代表根因消失；tombstone 趋势仍是当前最稳定恶化的指标。

### P0：flush 高频且没有退避

- 证据：`FLUSH=562`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=4255ms。
- 影响：每轮仍出现秒级完整重写，且在压力下已证明可放大到分钟级甚至 38 分钟级 outlier。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径缺少切分、退避和前台保护，是当前最主要的系统性风险。

### P1：trigram 路径中位数波动扩大

- 证据：`.pdf` 从 33.6ms 升至 98.8ms，`hello world` 从 41.4ms 升至 101.1ms，长查询 miss 从 34.1ms 升至 71.4ms。
- 影响：即使 Max 下降，更多查询从 <50ms 进入 50-100ms 区间，导致 P50 升高。

### P1：扫描类路径仍是尾部主因

- 证据：`path:/Users`=246.5ms，`中文测试`=187.7ms，`content:import`=159.6ms；full-scan 总和=737.7ms。
- 影响：本轮未接近 500ms，但扫描路径仍远高于健康 indexed/trigram 热路径。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，避免冲掉搜索路径 page cache。

### P0：提前或分段 compaction

- 不等待高全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 验收：tombstone 率从 12% 附近回落，full-scan 总和和常规 flush rewrite 同步下降。

### P0：降低 flush 频率并合并 WAL 批次

- 设置最小 flush 间隔和最大合并窗口。
- 对高 churn 目录减少完整重写次数，避免 `FLUSH` 计数持续快速增长。

### P1：拆分 trigram/postings 路径耗时

- 对 trigram 查询记录 postings 读取、候选集交并、排序、路径加载和结果组装耗时。
- 验收：解释 `.pdf`、`hello world`、长查询 miss 从几十毫秒跳到约 100ms 的原因。

### P1：拆分扫描路径耗时

- 对 `advanced-linear-gcd`、`advanced-pure-filter-soa-gcd` 记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 验收：能明确 `path:/Users`、`中文测试`、`content:import` 的主要瓶颈是扫描量、tombstone、排序还是 page-cache 冷却。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用预热或访问提示，减少 flush 后冷启动波动。
