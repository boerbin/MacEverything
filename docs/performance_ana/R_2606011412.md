## 9. 可能问题定位

### P0-1：中文 linear path 对 rewrite/page-cache 扰动高度敏感

证据：

- `中文测试` 在 W2/reprobe 中出现 `538.94 / 549.56 / 1036.33 / 622.14ms`。
- 日志记录同样新增 4 条 `中文测试` 慢查询。
- 这些慢查询发生在 14:11–14:13 连续 ≥5s rewrite 之后。

根因判断：中文 linear path 很可能访问字符串/路径/编码相关页，冷态 page fault 成本高于普通 path/content；rewrite cluster 后这些页被驱逐或 residency 变差，导致 1s 级锁内扫描。

### P0-2：锁内 full-scan 仍是尾延迟放大器

证据：

- `中文测试 battery total=191.65ms / lockHeld=191.36ms`。
- `content:import total=152.09ms / lockHeld=148.78ms`。
- `.pdf total=217.98ms / lockHeld=189.96ms`。

根因判断：慢页访问仍发生在锁持有区间。即使业务上只是一次查询，系统层面会把 page-cache 抖动转化为全局读写阻塞风险。

### P0-3：runtime reclaim 阀门太迟，tombstone ratio 已达 23.91%

证据：

- 本轮最终 `tombstoneRatio=23.91%`。
- `COMPACTION=2 / RECLAIM=0`。
- 相对上一轮，tombstones 增加 `30,771`，live records 只增加 `2,201`。

根因判断：当前负载持续制造 tombstone debt，扫描面和 rewrite 压力已在 23%+ 区间引发慢查询；25% 阀门明显过迟。

### P1：trigram 也出现冷态，但可快速热化

证据：

- `.pdf` battery `217.98ms`，但 reprobe floor `0.66ms`。
- `MacEverything` reprobe 首样本 `102.03ms`，后续 `1.37–1.85ms`。

根因判断：trigram 页也会受冷态影响，但热化更快，当前主风险仍是 full-scan / string / 中文路径。

## 10. 优化建议

### P0：为中文/path/content full-scan 增加 targeted prewarm

- rewrite 完成后优先预热中文匹配、path、content 相关字符串页，而不是只预热 trigram 索引。
- 目标是降低 rewrite 后第一批 full-scan query 的冷页成本，避免 `中文测试` 从 180ms floor 放大到 1s。
- 验收标准：连续 rewrite 后，`中文测试` W2/reprobe 不再出现 ≥500ms 样本。

### P0：增加 rewrite density guard

- 当前 14:11–14:13 连续 rewrite 后立刻出现中文慢查询 cluster，说明需要限制短窗口内 rewrite 密度。
- 建议在短时间内多次 ≥5s rewrite 时合并、推迟或降频后续 rewrite；当出现 ≥30s rewrite 后进入冷却窗口。
- 验收标准：`FLUSH_GE5` 增速下降，slow-query cluster 不再紧跟 rewrite cluster。

### P0：降低 runtime reclaim threshold 或改为 debt-based 复合触发

- 当前 `tombstoneRatio=23.91%` 已经接近 25%，但问题在 22–23% 时已经出现。
- 建议把阀值降到 8–10%，或按 `tombstone ratio + absolute tombstones + rewrite density + slow-query signal` 触发 reclaim。
- 验收标准：`RECLAIM>0`，tombstone ratio 回落到 10% 以下，full-scan floor 和 rewrite 时长不再随 tombstones 上升。

### P0：读写解耦，避免锁内承担 page fault

- 查询使用不可变 snapshot；flush/rewrite 通过 pointer swap 发布新版本。
- 优先处理 `advanced-linear-gcd` 和 `advanced-pure-filter-soa-gcd`，因为它们慢查询时 `lockHeld≈total`。
- 验收标准：当中文/path/content 出现 500ms+ 业务耗时时，`lockHeldMs / totalMs` 不再接近 1。

### P1：增加中文路径的列级与编码级观测

- 为中文 linear path 记录字符串 dereference 次数、编码匹配耗时、慢页估计、路径/内容列访问量。
- 将 `中文测试` 与 `path:/Users`、`content:import` 在相同 page 状态下对比，定位中文额外成本。
- 验收标准：解释 `中文测试 floor=186.57ms` 和 `max=1036.33ms` 的来源，并能区分编码计算与 page fault 成本。

## 11. 结论

本轮性能状态明显恶化：新增 4 条 `中文测试` ≥500ms 慢查询，最高 `1036ms`；同时 tombstone ratio 已达 `23.91%`，`FLUSH_GE5=166`，`RECLAIM=0`。这不是单次偶发，而是过去几轮 rewrite density 与 tombstone debt 持续累积后的结果。优先级应从“观察趋势”升级为 P0 修复：rewrite density guard、中文/path/content targeted prewarm、降低 reclaim 阀值、读写解耦。否则随着 tombstone ratio 逼近 25%，full-scan 慢查询 cluster 可能更频繁地出现。
