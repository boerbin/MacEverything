## 10. P0 优化建议（7 条 + 资源平衡说明）

1. **阀门下调 0.25 → 8–10%**（`IndexPersistence.cpp:159`）：墓碑七连涨至 21.98%、reclaim 恒为 0，阀门是墓碑只增不减的直接闸门。
2. **无锁快照刷新 / 读写解耦（TOP）**：本轮"缓降残留"现象（§2 W2 全面低于 R846 但未清空）是对"读路径与后台重写耦合"的最强证据——让查询读取不可变快照、flush 经指针交换发布新版本，可同时切断串行化争用与页缓存驱逐两条损伤通道。
3. **按簇密度的风暴护栏**（滚动窗口背靠背计数）：08:36–38 簇是上轮破窗源头；护栏应基于"窗口内重写次数"。
4. **全扫尾部护栏（string 线性层）**：path/中文/content 残留平台 170–220ms。为 linear-gcd 路径设预算 / 分段让出。
5. **dm 列驻留 / page-state**：dm 干净 52ms，但电池瞬时冲到 111ms（并发抖动）。固定列页驻留。
6. **string 读路径页驻留 / 重写后预热（本轮升格）**：缓降残留强烈指向"大重写驱逐 mmap 索引页、查询负载下逐页 re-fault 缓慢回暖"。应在大重写后主动预热 string 槽页，或用 `madvise(WILLNEED)` 锁定读路径热页。
7. **查询超时 / 熔断**：与分钟级重写并发的查询需 deadline + fail-fast。

**资源平衡说明**：7 条全部是 **I/O 调度 / 并发控制 / 页驻留**类改动，**无一以内存换计算或以计算换内存**。#2 无锁快照在 flush 期间额外占用"一个索引指针版本"的有界瞬时内存（交换后即释放）；#6 页驻留用 `madvise` 提示，不复制数据、不新增常驻大表，仅影响 OS 页回收优先级；#3/#7 为 O(1) 计数器/计时器。**未引入大内存表，未新增重计算**——内存与计算成本平衡。

## 11. 结论

🟠 **风暴退去，平台缓降——损伤机理被锁定为"随风暴累积的多小时缓降残留"**：①本轮无新增灾难性重写（距上次 06:16 约 3h），仅两次中等 ≥5s（08:55/09:02）；②**关键**——string 线性层 W2 地板全面低于 R846（path 196→167、中文 260→143、content 210→154）但仍约 R841 干净基线的 2.4–3×，即平台正以"分钟到小时"尺度缓降，**修正 R846 的"永久硬化"判断**；③这把三轮统一为一条曲线：R841 单稀疏簇→60s 清空；R846 紧邻密集簇→60s 不清空（高位）；R911 簇后 33min→缓降未清空。损伤量 ∝ 近期 flush 压力 × 邻近度，符合**大重写驱逐 mmap 索引页、查询负载下逐页 re-fault 缓慢回暖**的机理；④墓碑七连涨至 21.98%、SKIPFLUSH 单轮 +5（史上最大跳）、reclaim 恒为 0。证据集中指向 **P0#2 无锁快照刷新（根因，切断争用 + 驱逐两通道）**、**P0#6 string 读路径页驻留（本轮升格）** 与 **P0#1 阀门下调（墓碑闸门）**。

> **一句话**：风暴退去后，string 线性层平台从 R846 的"60s 不回落高位"缓降到本轮的 167–220ms（W2 地板全面低于 R846 但仍约干净基线 2.4–3×），把损伤机理锁定为"随风暴累积、风暴退去后多小时缓降的页缓存残留"，叠加 SKIPFLUSH 单轮 +5、墓碑七连至 21.98%、reclaim 恒 0，证据集中指向 P0#2 无锁快照刷新、P0#6 读路径页驻留与 P0#1 阀门下调。
