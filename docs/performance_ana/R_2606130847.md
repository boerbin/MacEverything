## 6. 问题清单

### P0：`中文测试` 几乎触发 500ms 慢查询阈值

- 证据：`中文测试` queryTimeMs=491.8ms，phase2Ms=483.9ms，日志 total=485ms，searchPath=`advanced-linear-gcd`。
- 影响：本轮虽未正式超过 500ms，但只差约 8ms，用户体感已经接近慢查询；历史同类查询已出现 608ms、716ms、555ms。
- 判断：主要耗时在 phase2 扫描阶段，不是 lockWait 或 HTTP 层；这是扫描路径结构性问题的复发信号。

### P0：tombstone 逼近 13%

- 证据：tombstone=788,196（12.96%），较上一轮增加 6,585。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：tombstone 已接近 13%，清理/compaction 触发明显偏晚。

### P0：flush 高频且没有退避

- 证据：`FLUSH=682`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=4200ms。
- 影响：完整重写仍维持秒级并持续污染 page cache，可能解释同一扫描查询在 142ms 到 492ms 之间大幅波动。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径缺少切分、退避和前台保护，是当前最主要的系统性风险。

### P1：扫描类路径波动扩大

- 证据：扫描类总和从 570.7ms 升至 822.8ms；`中文测试` 单项从 142.0ms 升至 491.8ms。
- 影响：平均值仍可接受，但尾部风险明显，下一轮很容易出现新的 `QUERYADV_GE500`。

## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 scan/filter 路径继续扫描大量无效记录。
- 验收：tombstone 率从 13% 附近回落，`中文测试`、`path:/Users`、`content:import` 稳定 <300ms。

### P0：为 advanced-linear-gcd 增加轻量剪枝

- 对中文和路径类无有效 trigram 命中的查询记录扫描记录数、tombstone 跳过数和 segment 分布。
- 评估轻量字符 n-gram、路径分段索引、预过滤位图或 segment-level skip list，以减少无结果查询的全量扫描。
- 要求保持内存增长可控，优先使用压缩或按需结构，不引入大常驻索引。
- 验收：`中文测试` 不再在 140-500ms 间大幅摆动，稳定低于 300ms。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页或持锁窗口。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier，lockWait 不再出现 50ms+。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，并评估大顺序写的 `F_NOCACHE`/同类策略，减少对搜索热页的冲刷。

### P1：拆分扫描路径耗时

- 对 `advanced-linear-gcd` 和 `advanced-pure-filter-soa-gcd` 记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 验收：能明确 `中文测试` 本轮 483.9ms phase2 的主要来源是扫描量、tombstone、排序还是 page-cache 冷却。

### P1：补充 lockWait 与后台状态关联观测

- 记录每次查询锁等待对应的 flush/update 状态、持锁线程、等待阶段和持锁耗时。
- 验收：确认当前 0ms lockWait 是真实无锁等待，而不是统计粒度不足；解释历史 `content:import` 67.6ms lockWait 来源。
