## 6. 问题清单

### P0：tombstone 已突破 10%

- 证据：tombstone=599,295（10.19%），较上一轮增加 14,445。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。
- 判断：10% 已经是明显的治理阈值，继续等待全局 25% 会让完整重写成本持续恶化。

### P0：latest session 新增 107 秒级 flush outlier

- 证据：`[2026-06-12 19:06:52.432] rewrite=106972ms total=107008ms`。
- 影响：即使不是 38 分钟级灾难，107 秒后台完整重写仍足以长时间污染 page cache 并拖慢前台热区。

### P0：38 分钟级 flush outlier 仍在 latest session 内

- 证据：`rewrite=2285476ms`、`total=2285536ms`。
- 影响：当前持久化路径在系统 I/O 压力下可以被极端放大，风险没有被根因修复。

### P0：flush 高频且无退避

- 证据：`FLUSH=415`，较上一轮 +10；`SKIPFLUSH=0`。
- 影响：完整重写持续运行，没有根据前台压力或历史 flush 耗时退避。

### P1：full-scan 恢复但仍偏高

- 证据：`content:import`=255.6ms，`path:/Users`=216.4ms，`中文测试`=223.2ms，full-scan 总和=695.2ms。
- 影响：已低于 500ms，但仍明显高于最佳轮次，说明 SoA/linear-gcd 热区仍受后台 I/O 影响。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 10%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA 热区使用 `madvise` 预热/保持。
