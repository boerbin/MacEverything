## 6. 问题清单

### P0：full-scan 前台性能重新超标

- 证据：`content:import`=531.8ms，`path:/Users`=466.8ms，`中文测试`=317.6ms，full-scan 总和=1316.2ms。
- 影响：内容/路径类查询重新进入用户可感知卡顿区间。
- 判断：trigram/ext-index 仍快，而 full-scan 明显回升，问题集中在 SoA/linear-gcd/full-scan 热区。

### P0：后台 flush 仍在 7 秒级

- 证据：最新 flush total=7199ms，rewrite=7141ms。
- 影响：秒级完整重写仍会持续污染 page cache，并与 full-scan 热区冷却高度相关。

### P0：38 分钟级 flush outlier 仍在 latest session 内

- 证据：`rewrite=2285476ms`、`total=2285536ms`。
- 影响：当前持久化路径在系统 I/O 压力下可以被极端放大，风险没有被根因修复。

### P0：tombstone 即将突破 10%

- 证据：tombstone=584,850（9.97%），较上一轮增加 8,234。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。

### P1：postings/ext-index 热区仍健康但不代表整体健康

- 证据：`.pdf`=26.0ms、`ext:cpp`=8.0ms、`hello world`=85.2ms。
- 判断：当前回归不是全路径退化，而是 full-scan/SoA 热数据受后台 I/O 影响更明显。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 10% 附近回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA 热区使用 `madvise` 预热/保持。
