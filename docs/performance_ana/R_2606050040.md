## 6. 问题清单

### High：偶发极端异常值——不可预测的秒级延迟

- `main.cpp` lockWait=1,567ms、`path:/Users` GCD=4,969ms、`content:import` phase2=2,794ms。
- **P50=116ms 但 Max=5,686ms——P99 延迟不可预测。**
- **原因**：flush rewrite（26.5s 峰值）+ WAL 批量写入 + 串行查询执行——三者偶发叠加。
- **用户感知**：大多数搜索即时响应，但偶尔某次搜索卡住数秒——体验不一致。

### Medium：Compaction 尚未触发——可能永远不触发

- 当前 19.49%，阈值 25%。
- **如果事件流继续减速（<1,000/min），tombstone 增长将非常缓慢**——可能数小时不触发 compaction。
- **风险**：系统停留在"不够好但不够坏"的中间状态——不会自动恢复到 R109/R115 水平。
- **建议**：考虑降低阈值或增加基于时间的触发条件。

### Medium：Index 文件持续膨胀

- recordCount=7.14M（live 仅 5.75M）——文件中 1.39M 行是 tombstone。
- 每次 flush rewrite 这 7.14M 行——比 compaction 后的 5.75M 多 24% 数据量。
- **flush rewrite 时间随 tombstone 增长**：5.75M→3s，7.14M→7s，R108 时 7.8M→最大 70s。

### 正面：事件风暴正在平息

- tombstone 增速从 24,000/min 降至 4,600/min——5 倍减速。
- 大多数查询（13/16）<500ms——trigram 引擎在 flush 间隙正常。
- lockWait 从 R116 的普遍性（3/16 高值）变为偶发性（1/16 极端）。

## 7. 优化建议

### P0：降低 Compaction 阈值至 15%

- 当前 25% 太高——系统在 17-25% 区间长期"亚健康"。
- **15% 阈值**意味着本轮（19.49%）早已触发 compaction——避免了整个 R116-R117 退化期。
- **权衡**：compaction 更频繁，但每次更快更轻量。

### P0：增加时间触发条件

- 即使 tombstone 不达阈值，**距上次 compaction >4 小时且 tombstone >5%** 也应触发。
- 避免系统停留在"亚健康"中间状态。

### P1：lockWait 极端值控制

- 单次 1,567ms lockWait 不可接受——WAL 写入应有最大持锁时间上限。
- **方案**：WAL 写入持锁超过 50ms 时强制释放（让出给等待的查询），下一轮再继续。
- **预期收益**：lockWait 上限从秒级降至 <50ms。

### P1：查询超时保护

- `path:/Users`=5,686ms 对用户来说是卡死。
- **方案**：查询增加 3 秒超时——超时后返回部分结果 + timeout 标记。
- **预期收益**：用户体验一致性——永远不卡超过 3 秒。

### P2：串行查询的 GCD 堆积消除

- `path:/Users` 的 4,969ms GCD 开销完全来自前序查询占用线程。
- **方案**：每个 HTTP 请求使用独立 GCD 队列，避免查询间的串行阻塞。

## 8. 下一轮重点

1. Tombstone 增速是否继续减速（<1,000/min 则 compaction 延迟触发）。
2. Compaction 是否在 ~02:10 触发，还是事件流停止后永远不触发。
3. 偶发极端异常值的频率——是否稳定在 1-3/16。
4. `x` short-query-cache 延迟是否恢复至 <20ms。

## 9. 结论

**部分恢复——P50=116ms（R116=909ms，↓7.8 倍），13/16 <500ms，但 3 个极端异常值仍达秒级（lockWait=1,567ms、GCD=4,969ms、phase2=2,794ms）。** tombstone 19.49%（1.39M），增速大幅减速至 ~4,600/min（R116=24,000/min，↓5 倍）——事件风暴正在平息。lockWait 从 R116 的普遍性（3/16）变为偶发性（1/16 极端+多个 <50ms）。**系统处于"亚健康"中间状态**——大多数查询快速响应，但偶发极端延迟不可预测。Compaction 阈值（25%）尚未触发——按当前增速还需 ~86 分钟。**根本问题**：25% compaction 阈值太高，导致系统在 17-25% 区间长期退化而不会自动恢复。建议降低至 15% 并增加时间触发条件。
