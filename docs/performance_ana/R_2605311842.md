## 10. P0 优化建议

1. **立即下调 `:159` 比率阀 0.25→8–10%**：墓碑 18.79%，连续 19 轮运行期 compaction=0；等待 25% 只会继续扩大 rewrite 成本。
2. **flush storm guard 继续作为 P0**：18:10 的 35.9s 主峰后仍有三次 5s 级 rewrite，guard 不能只看最近一次是否低于 10s，而应看滚动窗口中的连续 5s 级事件。
3. **lock-free snapshot flush**：本轮查询未命中主峰时表现可控，R126 命中余震时 path 1921ms；相位依赖仍证明读写解耦是根因级修复。
4. **mlock/madvise dm 列**：dm 仍 48–83ms，中位约 68ms，是数值层最脆弱锚点。
5. **查询超时/熔断**：虽然本轮无 ≥500ms 查询，但 R125/R126 已证明同一系统状态会在不同相位产生秒级阻塞。

## 11. 结论

- **定性**：主峰后查询侧部分恢复；底层风暴从 35.9s 主峰降级为 5s 级持续 rewrite，并未结束。
- **分裂**：**53/53** 维持；对抗口径约 1.63×，较 R126 明显放宽。
- **关键发现**：
  - 本轮电池、W1/W2、再探均无新增 ≥500ms 查询。
  - trigram/长查询再探回到毫秒级，R126 的长查询污染已消退。
  - 18:19–18:24 新增三次 ≥5s flush，证明底层仍在风暴态。
  - 墓碑 1.261M/18.79%，运行期 compaction 仍为 0。
- **根因判断**：不可回收墓碑继续扩大 rewrite 边界；查询是否慢取决于是否命中 flush/页态相位。本轮只是没有命中秒级窗口，不是结构恢复。
- **行动建议**：优先下调比率阀并加入 storm guard；随后做 lock-free snapshot flush 与 dm 列驻留，避免下一次 ingest 峰值再次制造 10s–30s 级主峰。
