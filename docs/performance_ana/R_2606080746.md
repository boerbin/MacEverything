### 原因分析

- **时段**：07:30-08:00 是 macOS 日间用户活跃高峰——应用启动、Spotlight 增量索引、iCloud 同步、邮件拉取等密集 I/O 并发。
- **机制**：大量外部进程的 sequential I/O 竞争 page cache，将 MacEverything 的 trigram postings 页面从 LRU 中淘汰。
- **线性扫描为何轻微**：linear-gcd（中文测试、path:/Users）本身是顺序读取，触发内核 readahead 预取，即使被淘汰也能快速重新加载。
- **trigram 为何重度**：trigram postings 是随机访问模式，被淘汰后每个页面需要独立 fault-in——延迟显著。
