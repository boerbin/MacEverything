## 9. 可能问题定位

### P0-1：runtime reclaim 阀门仍不可达，墓碑升至 22.66%
- 证据：R1143 末 tomb=1,604,844，ratio=22.66%；`RECLAIM=0`；已知阀门为 25%。
- 影响：扫描 working set 和 mmap page footprint 继续膨胀，full-scan 路径更容易受 page-state 扰动。
- 根因：25% 阈值对 22%+ 长期高压区间仍不敏感。

### P0-2：读路径冷页仍发生在锁内
- 证据：电池 `MacEverything` phase2=2.37ms，但 lockHeld=131.86ms；`.pdf` lockHeld=147.81ms；full-scan 慢项也满足 lockHeld≈total。
- 影响：一次冷页错失就能变成可见尾延迟，并阻塞共享读路径。
- 根因：查询 scan / trigram page access 与发布锁边界耦合过紧。

### P0-3：string/filter 页状态不稳定，低 floor 不能保持
- 证据：`path` W2 floor=108.97ms，但再探 floor=152.88ms；`content` W2 floor=113.53ms，但再探 floor=150.22ms；`中文` W2 floor=188.57ms。
- 影响：用户常见 path/content/中文查询仍在百毫秒平台，且容易受 flush 扰动。
- 根因推断：大 rewrite 后页自然回暖可短暂改善，但后续中等 rewrite 和 tombstone working set 扩大又推高平台。

### P1：flush 中等重写密度与 SKIPFLUSH 同时上升
- 证据：R1112 后新增 3 次 ≥5s rewrite，其中 11:33 与 11:34 相邻；`FLUSH_GE5 125→128`；`SKIPFLUSH 26→27`。
- 影响：当前未造成新 ≥500ms 查询，但会延缓 full-scan 平台清空。
- 根因：flush 调度与查询读路径共享 I/O/cache/锁资源，且 skip 语义不透明。

## 10. 优化建议

1. **将 runtime reclaim 阀门从 25% 下调到 8–10%**  
   当前 ratio=22.66% 仍无法触发 reclaim，墓碑继续单调上升。下调后应跟踪 reclaim 次数、rewrite 时长、full-scan floor、GE500 是否下降。

2. **读写解耦：查询读不可变快照，flush 通过指针交换发布**  
   本轮再次出现 `phase2 很低但 lockHeld 很高` 的 trigram 冷页证据。根因修复是缩短锁内区域，而不是只优化某个查询分支。

3. **对 trigram 与 string/filter 热页做 rewrite 后预热**  
   R1143 的广谱电池冷页说明不只 string 受影响，trigram 页也会被驱逐。预热应小范围覆盖 trigram 热页、path/name/content slot 页，使用 `madvise(WILLNEED)` 或顺序触碰，不复制完整索引。

4. **flush storm guard 按密度触发**  
   11:33–11:34 出现相邻 ≥5s rewrite，虽未造成 GE500，但符合“密度升高”的早期信号。guard 应按滚动窗口内 rewrite 次数/总时长触发。

5. **补充 SKIPFLUSH 与 flush debt 语义日志**  
   `SKIPFLUSH 26→27` 需要知道 skip reason、pending、阈值、距上次成功 flush 的间隔，才能判断是健康节流还是债务累积。

6. **full-scan 分段预算与让出**  
   在无锁快照完成前，给 `path/content/中文` 的 full-slot scan 加分段预算，降低单次不可中断窗口，减少百毫秒平台向 500ms tail 放大的概率。

**资源平衡说明**：以上建议优先调整阈值、锁边界、调度和 page hint，不引入大内存倒排表，也不要求额外重计算。预热应以 OS hint 或小范围顺序触碰为主；无锁快照只允许 flush 发布期间的有界短暂版本窗口。
