## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 linear-gcd/full-scan 继续扫描大量无效记录。
- 验收：tombstone 率从 12%+ 回落，`中文测试` 与 `path:/Users` 稳定 <300ms，full-scan 总和下降。

### P0：为 linear-gcd 扫描增加更细粒度索引或剪枝

- 对中文/路径类无有效 trigram 命中查询记录扫描记录数和跳过原因，找出是否可以用轻量字符 n-gram、路径分段或预过滤位图减少全量扫描。
- 要求保持内存增长可控，优先使用按需或压缩结构，而不是常驻大索引。
- 验收：`path:/Users` 和 `中文测试` 稳定低于 500ms，并能解释每次扫描规模。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，避免冲掉搜索路径 page cache。

### P1：拆分扫描路径耗时

- 对 `advanced-linear-gcd`、`advanced-pure-filter-soa-gcd` 记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 验收：能明确 `path:/Users`、`中文测试`、`content:import` 的主要瓶颈是扫描量、tombstone、排序还是 page-cache 冷却。

### P1：降低 flush 频率并合并 WAL 批次

- 设置最小 flush 间隔和最大合并窗口。
- 对高 churn 目录减少完整重写次数，避免 `FLUSH` 计数持续快速增长。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用预热或访问提示，减少 flush 后冷启动波动。
