## 6. 问题清单

### P0：linear-gcd 扫描路径重新突破 500ms

- 证据：`中文测试`=608.8ms，phase2=608.1ms，searchPath=`advanced-linear-gcd`，lockWait=0。
- 影响：这是本轮唯一前台超标项，说明扫描路径在数据规模、tombstone 和缓存状态共同作用下已经无法稳定守住 500ms。
- 判断：不是锁竞争导致的偶发等待，而是扫描阶段本身被放大。

### P0：tombstone 继续高于 12% 并上行

- 证据：tombstone=733,960（12.18%），较上一轮增加 6,864。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：现有 compaction/清理触发策略偏晚，已经开始和扫描尾延迟同时恶化。

### P0：flush 高频且没有退避

- 证据：`FLUSH=586`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=3588ms。
- 影响：秒级完整重写持续发生，会污染 page cache，并在 I/O 压力下放大为分钟级 outlier。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径缺少切分、退避和前台保护，是当前最主要的系统性风险。

### P1：pure-filter 扫描路径也处于高位

- 证据：`content:import`=306.6ms，phase2=288.1ms；`dm:today`=59.2ms；`size:>100m`=40.8ms。
- 影响：不同 pure-filter 查询分化明显，需要拆出扫描量、过滤成本、排序成本和 tombstone 跳过成本。

## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 linear-gcd/full-scan 继续扫描大量无效记录。
- 验收：tombstone 率从 12%+ 回落，`中文测试` 与 `path:/Users` 回到 <300ms，full-scan 总和下降。

### P0：为 linear-gcd 扫描增加更细粒度索引或剪枝

- 对中文/无 trigram 命中类查询记录扫描记录数和跳过原因，找出是否可以用轻量字符 n-gram、路径分段或预过滤位图减少全量扫描。
- 要求保持内存增长可控，优先使用按需或压缩结构，而不是常驻大索引。
- 验收：`中文测试` 稳定低于 500ms，并能解释每次扫描规模。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，避免冲掉搜索路径 page cache。

### P1：拆分扫描路径耗时

- 对 `advanced-linear-gcd`、`advanced-pure-filter-soa-gcd` 记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 验收：能明确 `中文测试`、`path:/Users`、`content:import` 的主要瓶颈是扫描量、tombstone、排序还是 page-cache 冷却。

### P1：降低 flush 频率并合并 WAL 批次

- 设置最小 flush 间隔和最大合并窗口。
- 对高 churn 目录减少完整重写次数，避免 `FLUSH` 计数持续快速增长。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用预热或访问提示，减少 flush 后冷启动波动。
