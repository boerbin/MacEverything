2. **`verylongquery`=29ms（phase2=0ms）**——与 R248=32ms 一致，连续两轮异常（通常 <3ms）——持续的系统级 overhead。
3. **`.pdf`=2511ms 中 phase2=2229ms**——搜索本身 2229ms，加上 282ms overhead。
4. **lockWait 回归**——6/16 查询出现 lockWait（max=11.2ms for `README`）。但 lockWait 值都很小（1-11ms），这不是 flush 写锁——更可能是系统级调度导致的锁等待延长。
