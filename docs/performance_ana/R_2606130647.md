## 6. 问题清单

### P0：tombstone 继续在 12% 以上上行

- 证据：tombstone=761,276（12.57%），较上一轮增加 6,376。
- 影响：无效记录比例继续升高，会放大扫描成本、索引重写成本与 compaction 压力。
- 判断：tombstone 已突破 12.5%，清理/compaction 触发明显偏晚。

### P0：扫描类路径持续高位

- 证据：`中文测试`=372.6ms，`path:/Users`=303.1ms，`content:import`=296.5ms；三者 phase2 分别为 372.2ms、291.2ms、284.1ms。
- 影响：本轮虽无 >500ms，但扫描路径仍占据 P90/Max，且最近一小时已出现过 608.8ms。
- 判断：主要耗时在 phase2 扫描阶段，不是 lockWait 或 HTTP 层。

### P0：flush 高频且没有退避

- 证据：`FLUSH=634`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=3444ms。
- 影响：完整重写持续污染 page cache，且在压力下已出现分钟级到 38 分钟级 outlier。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，23:24 flush total=735,223ms，19:06 flush total=107,008ms。
- 影响：持久化路径缺少切分、退避和前台保护，是当前最主要的系统性风险。

### P1：轻微 lockWait 重新出现

- 证据：`main.cpp` lockWait=0.5ms。
- 影响：不是本轮尾部主因，但在高频 flush/update 背景下需要关联后台时序，避免读写交叠发展成更大等待。

### P1：trigram 中位层出现波动

- 证据：`README`=59.5ms，`.pdf`=26.1ms，`*.swift`=33.4ms，`test`=28.5ms。
- 影响：trigram 路径整体健康，但 page-cache 或 postings 读取仍会让部分查询进入 50ms+ 区间。

## 7. 优化建议

### P0：立即提前或分段 compaction

- 不等待更高的全局 tombstone 阈值；结合绝对 tombstone 数、segment tombstone 率和 flush rewrite 成本触发局部 compaction。
- 优先处理 tombstone 密集 segment，避免 linear-gcd/full-scan 继续扫描大量无效记录。
- 验收：tombstone 率从 12%+ 回落，`中文测试` 与 `path:/Users` 稳定 <300ms，full-scan 总和下降。

### P0：为 linear-gcd 与 pure-filter 扫描增加剪枝

- 对中文、路径、content/filter 类查询记录扫描记录数和跳过原因，评估轻量字符 n-gram、路径分段、预过滤位图或 segment-level skip list。
- 要求保持内存增长可控，优先使用按需或压缩结构，而不是常驻大索引。
- 验收：`path:/Users`、`中文测试`、`content:import` 稳定低于 300ms，并能解释每次扫描规模。

### P0：flush 改为增量/COW 页写入

- 将 stable segment 与 delta segment 分离，常规 flush 只追加或替换小段 delta。
- 大段合并放到后台低优先级任务，不与前台查询争抢热页。
- 验收：常规 flush total <200ms，latest session 不再出现分钟级 rewrite outlier。

### P0：增加 flush I/O 压力退避和前台保护

- 当最近 flush 超过阈值时，提高下一次 flush 间隔或降低 batch 频率。
- 前台查询活跃或 I/O 延迟升高时推迟大 flush。
- 持久化线程使用低 QoS，避免冲掉搜索路径 page cache。

### P1：补充 lockWait 与后台状态关联观测

- 记录每次查询锁等待对应的 flush/update 状态、持锁线程和等待阶段。
- 验收：确认 `main.cpp` 这类轻微 lockWait 是偶发读写交叠，还是高频 flush/update 周期性触发。

### P1：拆分扫描路径和 trigram 路径耗时

- 对扫描路径记录扫描记录数、tombstone 跳过数、过滤耗时、排序耗时和结果组装耗时。
- 对 trigram 路径记录 postings 读取、候选集交并、排序、路径加载和结果组装耗时。
- 验收：能解释扫描路径 300ms+ 与 trigram 50ms+ 的具体来源。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用预热或访问提示，减少 flush 后冷启动波动。
