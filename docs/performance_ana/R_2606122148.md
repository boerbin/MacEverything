## 6. 问题清单

### P0：多路径前台热区同步冷却

- 证据：`.pdf`=341.9ms，`hello world`=213.2ms，`path:/Users`=477.5ms，`中文测试`=296.4ms。
- 影响：虽然没有超过 500ms，但多个常见路径已进入用户可感知卡顿边缘。
- 判断：不是单个 query 异常，而是 postings、filter、full-scan 多路径同时受 page-cache/I/O 状态影响。

### P0：tombstone 持续高于 10%

- 证据：tombstone=603,572（10.25%），较上一轮增加 4,277。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。

### P0：latest session 仍包含分钟级/超长 flush outlier

- 证据：19:06 flush total=107,008ms，13:02 flush total=2,285,536ms。
- 影响：长时间完整重写持续污染 page cache，并解释前台查询的周期性波动。

### P0：flush 高频且没有退避

- 证据：`FLUSH=418`，较上一轮 +3；`SKIPFLUSH=0`。
- 影响：即使最新一次 flush 降到 1980ms，后台完整重写仍持续发生，风险没有根除。

### P1：full-scan 再次接近超标

- 证据：`path:/Users`=477.5ms，full-scan 总和=1053.2ms。
- 影响：下一轮如果 I/O 压力稍增，`path:/Users` 很可能再次突破 500ms。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 10%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA 热区使用 `madvise` 预热/保持。
