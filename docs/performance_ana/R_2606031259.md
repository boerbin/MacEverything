## 6. 问题清单

### Critical：`x` 短查询缓存路径异常（254ms）

- 证据：`x` 走 short-query-cache 路径，前 9 轮稳定在 4-21ms，本轮飙升至 254ms。
- phase2Ms=0，lockWaitMs=0，说明延迟不在搜索引擎内部。
- 可能原因：短查询缓存失效/重建、系统级 I/O 压力导致缓存读取变慢、或 GCD 调度延迟。
- 影响：如果缓存路径不稳定，短查询的用户体验将不可预测。

### High：tombstone 突破 100K（1.73%，100,678 条）

- 证据：十轮轨迹持续上升（4K → 6K → 17K → 34K → 45K → 59K → 67K → 75K → 83K → **101K**）。
- 增速稳定约 8,000-14,000 条/轮。
- SKIPFLUSH=48，flush-triggered compaction 路径完全休眠。
- **预计约 5-8 轮后将突破 2% 阈值。**

### High：`.pdf` 接近 500ms 阈值（488ms）

- lockWaitMs=4.8ms 再次出现（R54 后第二次）。
- phase2=418ms，candidates=9944（不变），I/O 负载导致 phase2 验证变慢。

### Medium：整体 I/O 负载导致广泛退化

- `main.cpp` 14→164ms，`*.swift` 62→271ms，`content:import` 165→355ms。
- lockWaitMs 仅在 `.pdf` 出现微量（4.8ms），主要退化在 phase2 阶段。
- 与前两轮（R56/R55 历史最佳）形成鲜明对比，说明系统 I/O 负载是主导因素。
