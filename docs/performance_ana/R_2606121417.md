## 6. 问题清单

### P0：38 分钟级 flush outlier 仍是最新 session 最大风险

- 证据：`rewrite=2285476ms`、`total=2285536ms`。
- 影响：后台持久化长时间占用 I/O，极可能导致 13:53 的 `.pdf` 与 `path:/Users` 前台慢查询。
- 根因：完整索引重写在 APFS COW、系统 I/O 压力、睡眠/唤醒或后台任务竞争下被极端放大。

### P0：常规 flush 仍在 4 秒级

- 证据：最新 flush total=4664ms，rewrite=4657ms。
- 影响：即使本轮前台恢复，后台 flush 仍足以在下一轮再次冷却 page cache。

### P0：flush 频率继续上升且没有退避

- 证据：最新 session `FLUSH=324`，较上一轮 +10；`SKIPFLUSH=0`。
- 影响：高频完整重写持续污染 page cache，并扩大下一次慢查询风险。

### P0：tombstone 继续逼近 9%

- 证据：tombstone=517,127（8.93%），较上一轮增加 6,582。
- 影响：索引体积、flush rewrite 成本和扫描成本继续扩大。

### P1：full-scan 恢复不充分

- 证据：full-scan 总和 981.5ms → 744.9ms，虽恢复但仍高于 12:18 的 586.0ms。
- 影响：`content:import`、`path:/Users`、`中文测试` 仍在 227-259ms 区间，未回到低位。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 8.9%+ 回落，并且常规 flush rewrite 时间下降。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对搜索热区使用 `madvise` 预热/保持。
