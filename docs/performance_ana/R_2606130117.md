## 6. 问题清单

### P0：tombstone 继续升高到 11.45%

- 证据：tombstone=683,770（11.45%），较上一轮增加 10,558。
- 影响：索引体积、flush rewrite 成本、扫描成本和 compaction 压力继续扩大。
- 判断：tombstone 已连续多轮高于 11%，必须提前或分段治理。

### P0：flush 高频且没有退避

- 证据：`FLUSH=502`，较上一轮 +12；`SKIPFLUSH=0`；最新 flush total=3557ms。
- 影响：秒级完整重写持续污染 page cache，是前台冷热波动的主要背景风险。

### P0：latest session 仍包含灾难级 flush outlier

- 证据：13:02 flush total=2,285,536ms，03:15 flush total=896,053ms，19:06 flush total=107,008ms。
- 影响：持久化路径在 I/O 压力下可被极端放大，前台查询当前未超标不代表根因消失。

### P1：`.pdf` top-level 耗时异常偏高

- 证据：`.pdf` queryTimeMs=281.7ms，但 phase2Ms=70.7ms，lockWait=0。
- 影响：耗时主要不在 phase2 或锁等待，可能来自结果 materialization、排序、路径读取、JSON 序列化或请求线程调度。

### P1：扫描类路径仍是尾延迟主要来源

- 证据：`content:import`=182.4ms，`path:/Users`=209.3ms，`中文测试`=210.9ms，full-scan 总和=602.6ms。
- 影响：虽然较上一轮继续恢复，但仍明显高于极佳区间，且受 tombstone 增长和后台 I/O 影响。

### P1：轻微锁等待仍需观察

- 证据：`中文测试` lockWaitMs=1.9ms；上一轮 `.pdf` lockWaitMs=36.5ms。
- 影响：当前不是主因，但连续两轮出现不同查询的 lockWait，需关联 flush/update 时序。

## 7. 优化建议

### P0：flush 改为增量/COW 页写入

- 分离 stable segment 与 delta segment；常规 flush 只追加 delta。
- 后台低优先级合并，不阻塞前台查询。
- 验收：flush rewrite max <200ms，latest session 不再出现分钟级 outlier。

### P0：为 flush 增加 I/O 压力退避和前台保护

- flush 超过阈值后降低下一轮频率。
- 前台查询活跃时推迟大 flush。
- 持久化线程使用更低 QoS，减少对搜索热路径的干扰。

### P0：提前或分段 compaction

- 不等待全局 25% tombstone 阈值。
- 按 segment 或绝对 tombstone 数触发局部 compaction。
- 验收：tombstone 率从 11%+ 回落，并且常规 flush rewrite 时间下降。

### P0：降低 flush 频率并合并 WAL 批次

- 引入最小 flush 间隔和最大合并窗口。
- 对高 churn 场景减少完整重写次数。

### P1：拆分 top-level 非 phase2 耗时

- 对 HTTP handler、结果 materialization、排序、路径读取、JSON 序列化分别打点。
- 优先定位 `.pdf` 这类 phase2 中等但 top-level 显著偏高的查询。

### P1：补充 postings/trigram 与 lockWait 观测

- 对 postings 读取、候选集构造、排序、结果 materialization 分别打点。
- 记录每次查询锁等待对应的后台 flush/update 状态，判断 lockWait 是否由 flush 或索引更新交叠引起。

### P2：保护搜索热数据 page cache

- 对 flush 大顺序写考虑 `F_NOCACHE` 或同类策略。
- 对 full-scan/SoA/postings 热区使用 `madvise` 预热/保持。
